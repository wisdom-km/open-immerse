## 1. 一句话

PDF 带 arXiv 编号时，用户点一下，就下载作者上传的 LaTeX 源码包，从里面取公式，用 KaTeX 显示。每个公式都要先和用户打开的这份 PDF 核对通过才上屏，没过就按 REQUIREMENTS §2.6 的运行时顺序（多模态 → 矢量重绘 → 裁图 → 占位）走。PDF 仍是准绳，源码只是帮我们更准地还原这份 PDF。

在 Attention v7 上，原型的结果是：要翻译的段落 108/108 对上（104 块 ≥90% 的词对上），独立公式 5/5 找到位置、5/5 字符一致、编号 3/3 一致；源码正文里的行内公式共 87 个，找到位置 85 个（85/87），字符一致 83 个（83/87）。

## 2. 设计

### 2.1 认出 arXiv 编号（P1）

Attention v7 里实际有的线索：

| 线索 | 实测 | 用不用 |
| --- | --- | --- |
| 第 1 页左边竖排的 arXiv 戳 | `arXiv:1706.03762v7 [cs.CL] 2 Aug 2023`，在文字层里，旋转 90°，只在第 1 页 | 用，最可靠，带版本号 |
| 打开时的网址 | 从 arxiv.org 的 PDF 标签页打开时，`popup.js` 把网址作为 `?src=` 传进来，例如 `https://arxiv.org/pdf/1706.03762v7` | 用。网址可能不带版本号，`/pdf/1706.03762` 指最新版 |
| pdf.js Info 字典、XMP、DOI | 都没有编号 | 不用 |
| 文件名 | 夹具文件名里没有编号；arXiv 默认下载名是 `1706.03762v7.pdf` | 第一版不用（决定 7 只认戳和网址） |
| 参考文献里的 arXiv 号 | 第 10–12 页有 `arXiv:1607.06450` 等别的论文的编号 | **陷阱**，不能全文搜 |

判定顺序：

1. 网址是 `arxiv.org/pdf/<id>[vN]` 或 `arxiv.org/abs/<id>[vN]` 时，取编号。
2. 第 1 页页边竖排的戳，正则 `arXiv:(\d{4}\.\d{4,5}|[a-z-]+(\.[A-Z]{2})?/\d{7})(v\d+)`，取编号和版本。只看第 1 页、旋转过的、贴着页边的文字项（初始值，待确认；已确认的只是「PDF 上的 arXiv 戳」，没说第 1 页）。和第 1 条冲突时以戳为准，因为戳描述的就是这份 PDF。
3. 都没有：不启用源码模式。第一版不为出版社 PDF 按题名或 DOI 反查（CVF 版 ResNet 实测只有 80.8% 的词对得上，见 §2.5）。

### 2.2 下载（P2）

实测（box 上用 curl，每次请求间隔 ≥3 秒）：

| 项 | 结果 |
| --- | --- |
| `arxiv.org/e-print/1706.03762v7` | 301 跳到 `/src/1706.03762v7` |
| `arxiv.org/src/1706.03762v7` | 200，`application/gzip`，1,150,988 字节，回 `Access-Control-Allow-Origin: *` |
| 不带版本号 | `/src/1706.03762` 给的是 v7（最新版） |
| v1 | `/src/1706.03762v1`，1,128,925 字节，目录结构和 v7 不同 |
| 单文件投稿 | `hep-th/9711200`：`.gz` 解开就是一个 .tex，而且是 plain TeX |
| 只有 PDF 的投稿 | 没找到例子实测。按 arXiv 文档，这时返回的是 PDF 本身（开头 `%PDF-`） |

扩展这边：

- `manifest.json` 已经有 `"host_permissions": ["<all_urls>"]`，扩展（含 service worker）发 fetch 不受 CORS 限制，**不用加权限**。
- 联网下载放在 `background/`（service worker）里，守住 README「网络与缓存只在 `background/`」这条约定。阅读器页面发消息（暂定 `OI_ARXIV_SOURCE`，带编号和版本）给 service worker；service worker 查缓存，没有才下载、解包、存进 IndexedDB，只把源码文本回给页面。service worker 里也有 `fetch`、`DecompressionStream` 和 IndexedDB，不用加权限。（仓库里本地库 `lib/pdf-library.js` 和划区请求是从阅读器页面直接 fetch 的，那是现有的例外，这次不动。）
- 只用 e-print 源码包，第一版不用 arXiv HTML（决定 8）。

**robots 和礼貌（实现初始值，待确认；「点了才下」「以后自动」是已确认的）：**

- `arxiv.org/robots.txt` 对所有爬虫 Disallow `/e-print` 和 `/src`，Crawl-delay 15。我们不是爬虫：用户自己打开一篇论文、自己点一下，只下这一篇。为此建议守住：
  - 只在用户点了「用 arXiv 源码校准公式」，或之前勾了「以后自动」时才下（已确认）；
  - 一篇（编号 + 版本）只下一次，之后读本机缓存；
  - 不预取，不批量，不在后台扫库；
  - 全局每 3 秒最多一个请求，同时只开一个连接（arXiv API 使用条款的口径）；
  - 超时 20 秒；403 或 429 之后一段时间内不再请求（初始值 24 小时），本次会话失败过的编号不再重试。
- 条款：arXiv 允许个人使用或研究时取用、保存 e-print 内容，**不能在自己的服务器上存储或提供**。所以源码只在用户本机解析和缓存，不上传，不经本地库服务转发，不进仓库。
- 用户在国内，arxiv.org 一般能连但可能慢。下载放后台，不挡住原页显示，超时就按 PDF 流程走。
- 隐私：下载会让 arXiv 知道用户在读哪篇论文（以及用户的 IP）。这是默认关闭、点了才下的原因。REQUIREMENTS §2.7「网络和隐私」也写了这一条。

### 2.3 解包（P2）

- 在 service worker 里做（见 2.2）。解包函数本身是纯函数，放 `lib/`，由 `background/` 调用，方便测试。
- 不加新依赖：用 Chrome 自带的 `DecompressionStream('gzip')`（manifest 要求 Chrome ≥114，够用），加一个约 40 行的 ustar 读取器。原型 `arxiv-src-unpack.mjs` gzip 后 1.1 KB。
- 判断格式：先看开头是不是 `%PDF-`（只有 PDF 的投稿）；再看是不是 gzip；解开后第 257 字节处是不是 `ustar`，是就是 tar，不是就是单个 .tex。
- 安全：处理 GNU 长文件名和 pax 头；挡掉 `..` 和绝对路径；只收普通文件；限制文件数和总大小（初始值：2,000 个文件、解开后 50 MB）。
- 只留文本文件（.tex、.bbl、.sty、.cls、.bib 等），图片丢掉。Attention v7 包里 23 个文件，.tex 加起来约 80 KB。
- 实测：v7 解包加列文件 185 ms（node 首次运行），v1 41 ms。

### 2.4 LaTeX 解析（P3）

1. 找主文件：同时有 `\documentclass` 和 `\begin{document}` 的那个。Attention 是 `ms.tex`，唯一一个。
2. 先去注释，再从主文件顺着 `\input` / `\include` 走。**不能把包里的 .tex 全拿来用**：Attention 包里有 `parameter_attention.tex`、`sqrt_d_trick.tex`，引用它们的那行被 `%` 注释掉了。
3. 收集 `\newcommand`、`\def`、`\DeclareMathOperator` 并展开。Attention 有 16 个，例如 `\dmodel` → `d_{\text{model}}`。正文里写的宏定义要去掉，不能当成公式（ResNet 上踩过）。
4. 切成单元：标题、作者、章节标题（自己按 LaTeX 规则算 3.2.1 这类编号）、段落、`itemize` 条目、独立公式（equation / align / `\[ \]` / `$$`，并算出公式编号）、浮动体题注（算出「Figure 1:」「Table 2:」）、脚注、参考文献条目（`thebibliography` 或 `.bbl`）。段落里的 `$…$`、`\(…\)` 记为行内公式。
5. 渲染前处理：`\label`、`\nonumber`、`\tag` 去掉或改写（ResNet 两个公式带 `\label`，不去掉 KaTeX 会报错）；`align*` 包成 `aligned`。
6. KaTeX 不认的宏或环境（`\SI`、`\qty`、TikZ、plain TeX 等）：这个公式不走第零层。**运行时不猜宏。** 找不到主文件、整篇是 plain TeX：整篇不走第零层。
7. 第 1 页的许可声明（Attention 的「Provided proper attribution…」）PDF 流程有意滤掉了（`lib/pdf-readout.js` 的 `PERMISSION_RE`），源码这边套用同样的过滤。

Attention v7 的解析数字（P3 测试要锁住）：独立公式 5、行内公式 98（正文 87，题注和脚注 11）、章节标题 25、宏 16。仓库自带的 KaTeX 0.18.7 能渲染全部 5 个独立公式和 98 个行内公式（`throwOnError: true`）。

### 2.5 对齐和逐条核对（P4）

**做法：**

1. PDF 这边不另起炉灶，直接用仓库现有 `textLayerToBlocks` 产出的块（右栏用的就是这些），包括块里的 `⟦fN⟧` 占位和行内公式块。
2. 第一遍：正文按阅读顺序，对两边的词序列做单调对齐（最长公共子序列）。词先小写，去掉重音、连字符和引用号 `[5, 2, 35]`。再补一步拼接修复：行末断词，或 `$d_v$-dimensional` 这种公式紧贴连字符的情况。
3. 第二遍：题注、脚注、作者这些浮动的东西，和第一遍没对上的段落，单独去找剩下的 PDF 块，按词重合度挑最好的，≥0.6 才算对上。
4. 公式定位：看源码里公式前后紧挨着的词在 PDF 里对到哪儿，公式就在两者之间。独立公式找中间的 PDF 公式块；行内公式找中间的 `⟦fN⟧` 公式块，或 PDF 正文里的明文（比如 `N = 6`）。一句里连着几个公式、中间没有词的，合成一组一起比。
5. 逐条核对（每个公式都要过，缺一条就不用源码）：
   - **位置**：上一步找到了位置；
   - **字符**：LaTeX 先按 REQUIREMENTS §2.6「第二层核对」的映射表转成字符，两边做 NFKC，和 PDF 那块区域里的字形比字符集合。独立公式先去掉右边的编号 `(n)`。初始门槛是集合完全相等（原型就是这么判的），比第二层的 Jaccard ≥ 0.9 更严。映射表和第二层共用一份代码；
   - **编号**：独立公式的编号用源码算出来的，和 PDF 右边的 `(n)` 比；
   - **渲染**：KaTeX `throwOnError: true` 不报错。
6. 原型用的是 O(n·m) 的动态规划，Attention 要 23 MB 内存，50 页的论文会到几百 MB。正式实现先用只出现一次的 n-gram 当锚点切段，段内再做动态规划，内存要有上限。

| 词数 | 源码正文 4,692 词，PDF（不含题注）4,908 词，对上 4,583 词，拼接修复 11 处，约 200 ms |

**版本不一致：源码 v1 对 PDF v7**

| 项 | 结果 |
| --- | --- |

### 2.6 右栏显示和翻译（P5）

- 公式用仓库已带的 KaTeX 0.18.7（`viewer.html` 已经加载），不增加体积。`pdf/viewer.js` 里定义了 `renderFormulaNode`，但现在的新路径没有调用它（ARCHITECTURE §11）；P5 再决定复用它还是另写渲染函数。
- 第一版只换公式：独立公式和行内公式（决定 3）。段落原文和译文仍用 PDF 文字层的块文字。理由：PDF 文字已有 97.5% 和源码一致；源码里没有引用编号和交叉引用编号，这些数字 PDF 里才有。
- 翻译沿用现有 `⟦fN⟧` 占位协议（`lib/pdf-blocks.js` 的 `PLACEHOLDER_RE`、`PDF_PROMPT_ADDENDUM`）：行内公式送翻译前换成 `⟦fN⟧`，回来再换成 KaTeX。公式不进模型。
- 现在显示成明文的行内公式（如 `N = 6`、`d_{model}`），有源码时会变成真正的公式。这是最直接看得到的改进。
- 点公式跳回原文：用对齐到的 PDF 块的 `page + bbox`，和现在一样。
- 单个公式不加记号（决定 4）。状态栏写一句总的。文案以 Loom 规格为准，示例：「公式来自 arXiv 源码 v7：独立 5/5、行内 83/87 已核对」。分母统一用源码里该类公式的总数（Attention 正文行内 87 个），分子是核对通过、真正上屏的个数。决定 4 的选项原文示例写的是「行内 83/85」（分母是找到位置的 85 个），这里统一成总数，免得两种口径混用。
- 块协议：过了核对的公式带 `latex`、`latexSource: "arxiv-src"`、`verified: true` 三个字段，缺一则丢弃（REQUIREMENTS §6）。
- KaTeX 是重新排版，内容一致，但换行和间距可能和原页有细小差别。

### 2.7 退回（每一步失败都按 PDF 流程走，不弹错，只在状态里写一句）

| 情况 | 做法 |
| --- | --- |
| 认不出 arXiv 编号 | PDF 流程（现状） |
| 有编号，用户没点 | PDF 流程；状态栏给「用 arXiv 源码校准公式」 |
| 下载失败、超时、离线、403 / 429 | PDF 流程；本次会话不再重试；403 / 429 后一段时间内不再请求（初始值 24 小时） |
| 只有 PDF 的投稿（返回 `%PDF-`） | PDF 流程；缓存「此编号无源码」 |
| plain TeX，或找不到主文件 | PDF 流程 |
| 版本对不上或不知道版本 | 下最新版，照样对齐，只用通过核对的公式 |
| 整篇要翻译的词对齐率 < 85% | **建议，待确认**：整篇不用源码，状态栏写「源码与此 PDF 差别较大」。不采用时只按公式退回（下一行） |
| 某个公式没找到位置、字符不一致、编号不一致或 KaTeX 渲染失败 | 这个公式按 REQUIREMENTS §2.6 的运行时顺序走：多模态 → 矢量重绘 → 裁图 → 占位（决定 5；顺序 2026-10-05 改） |

### 2.8 缓存

- 源码按「编号 + 版本」存；对齐结果按「编号 + 版本 + PDF sha256」存（仓库已有 `pdfByteHash`）。第二次打开同一份 PDF 不再联网。
- 只存文本文件，Attention 约 80 KB/篇。放扩展自己的 IndexedDB（`chrome.storage.local` 在没有 `unlimitedStorage` 时上限 10 MB，不合适）。
- 设置里给「清除 arXiv 源码缓存」。
- 不传到本地库服务（`127.0.0.1:8765`），不上传，不进仓库（决定 9）。
- 读写缓存都在 `background/` 里（见 2.2）。

## 3. 分期（每期一个 PR）

测试统一用 Attention v7 PDF 夹具。源码包也做成 gitignored 的本地夹具（决定 10），**永不提交**：

| --- | --- |
| `tests/fixtures/arxiv-src/1706.03762v7.tar.gz` | `2e7a7d9ee2520d22eb23dae0cb148e167be02a30d6cb3f11b1c67723194339c6` |
| `tests/fixtures/arxiv-src/1706.03762v1.tar.gz` | `377b47ecf3cd8638f7214184cc445cb378b37b5f0ddb42981b1ad288b3a1c03b` |

- P2 的第一个提交先在 `.gitignore` 加 `tests/fixtures/arxiv-src/`，再放夹具。

## 4. 风险

1. **arXiv 的态度**：robots 不让爬虫下 `/src`。用户触发、一篇一次、本地缓存，算正常的人工使用；用户多了仍可能被限流或封 IP（403）。对策：严格限速，403 后长时间不请求，必要时联系 arXiv。
2. **版权**：只能在本机用，不上传、不进仓库、不经本地库服务转给别人。Attention 这篇的许可证种类没查。
3. **解析覆盖面**：真实论文的宏和包五花八门。Attention 很顺，ResNet 就露了毛病（表格宏、正文里的宏定义）。对策：解析不了的一律退回，不硬猜；在更多 arXiv 论文上量覆盖率。
4. **版本漂移**：v1 对 v7 整体降到 89.8%。逐条核对挡得住，但会有一部分公式退回第一层。
5. **出版社 PDF 和 arXiv 版内容不同**：ResNet 只有 80.8%。这是第一版不做反查的原因。
6. **字符集核对不是万能的**：不比顺序和次数，`x^2` 和 `2x` 字符集相同。源码公式本来就是作者写的，核对主要防「对错位置」，不是防「写错」。
7. **KaTeX 是重新排版**：内容对，但不是原页像素。现在的验收口径是「同一套内容」，可以接受。
8. **性能**：全文对齐的内存要有上限；下载约 1 MB，放后台，不挡原页。
9. **隐私**：下载会让 arXiv 知道用户在读哪篇。所以默认关闭，点了才下。
10. **范围膨胀**：新管线会和第一层、第三层、held-out 抢时间。P1–P4 小步走，P5 等规格。

**没验证过的：** 只有 PDF 的 arXiv 投稿（没找到例子）；Chrome 扩展里实跑下载、解包和渲染（只在 node 里跑过）；arXiv HTML 的对齐；国内网络下 arxiv.org 的速度；出版社 PDF 只测了一篇。

## 5. 「100%」指什么

能说的：同一版本下，源码就是 arXiv 编译这份 PDF 用的原稿，所以源码公式就是 PDF 想表达的内容，不会有「认错 i 和 n」这类识别错误。Attention v7 上独立公式 5/5 和 PDF 字形核对一致；正文行内公式共 87 个，找到位置 85 个，其中 83 个核对一致（83/87）。找到但不一致的 2 个是原型分词的毛病；没找到的 2 个是 PDF 流程的公式框吞了正文、锚没了（见 2.5）。

不能说的：不是任何 PDF 都 100%（没源码、只有 PDF 的投稿、出版社版本都回到现有流程）；不是像素级一样；版本不同就不是同一份内容；我们的解析器和 KaTeX 不是 TeX 引擎；图仍是图，表仍整表当图；引用编号、交叉引用编号、页码仍取自 PDF。

对外说法：**「有 arXiv 源码时，公式取自作者原稿，并逐条与 PDF 核对。」** 不写「100%」。
