### 1. 产品定位与多端分工

open-immerse 的核心目标是成为科研人员的**个人研究操作系统**：以结构化文献库为知识底座，覆盖「读 → 理解 → 记 → 想 → 写」的完整链路，并通过不同端适配不同场景。

| 端 | 核心场景 | 主要能力 | 设计原则 |
|----|----------|----------|----------|
| **桌面端**（扩展 + Electron） | 深度阅读 + 论文写作 | 高精度 PDF 对照、公式精准呈现、笔记、文献管理、LaTeX 写作辅助与导出 | 大屏、精确操作、长时间沉浸 |
| **手机端** | 听论文 + 轻量回顾与捕捉 | 论文播客/讲解音频、语音问答、快速回顾、语音笔记、轻量写作灵感 | 碎片时间、听觉优先、低认知负担 |
| **共享底座** | 知识库 | 文献、译文、块、笔记、写作项目、引用关系 | 一次处理，多端复用 |

**关键原则**：
- 桌面负责“深读 + 写作产出”。
- 手机负责“听懂 + 记住 + 灵感捕捉”。
- 写作内容与阅读内容进入同一知识库，形成闭环。
- 手机支持轻量写作（语音转段落、大纲补充），但重编辑仍在桌面。

### 2. 设计原则（补充）

在原有原则基础上增加：

- **知识库统一**：阅读产生的结构化内容（块、译文、笔记）与写作项目共享同一套数据模型与检索能力。
- **场景适配而非功能复制**：手机不做完整 PDF 阅读器，桌面不做以音频为主的消费界面。
- **写作渐进**：先做“基于知识库的生成与导出”，再考虑轻量编辑器，避免过早与 Overleaf 竞争。
- **听觉化一等公民**：音频生成、播放、章节导航作为手机端核心路径设计，而非附加功能。

### 5. 知识库与写作域设计

**统一知识库**以文献为核心实体，扩展写作项目：

- `Document`：论文（含原文、译文、块、公式决策、笔记锚点）。
- `Note`：用户笔记（可挂到块或独立）。
- `WritingProject`：写作项目，关联多个 `Document`。
- `Section`：论文章节（Introduction、Related Work 等），可包含生成内容与用户编辑。
- `CitationLink`：写作内容与来源论文/块的引用关系。

**写作流程（桌面为主）**：
1. 从文献库选择相关论文创建 `WritingProject`。
2. AI 基于关联论文 + 用户笔记/想法生成大纲与初稿段落（LaTeX）。
3. 用户在桌面编辑器中修改，系统维护引用关系。
4. 一键导出标准 arXiv 风格 LaTeX 项目。

**手机轻量写作**：
- 语音输入想法 → 自动归入某个 `WritingProject` 的对应章节。
- 生成或补充段落草稿，回桌面后可继续编辑。

### 6. 手机端听觉化设计

手机端以「听论文」为核心路径：

- **播客生成**：基于译文 + 块结构 + 用户笔记，生成 10–15 分钟结构化讲解（贡献、方法、实验、局限）。
- **按需讲解**：语音或点击触发“讲一下这个公式 / 这个章节”。
- **语音问答**：结合论文内容与历史笔记进行对话，支持语音输入输出。
- **播放体验**：章节导航、倍速、后台播放、进度与桌面阅读位置关联（可选）。
- **轻量回顾**：打开论文优先展示“上次听到哪里 + 关键卡片 + 我的笔记摘要”。

音频脚本生成放在 `core/audio/`，TTS 调用通过 `platform` 适配（支持云 API 与本地模型）。

### 7. 多端数据与同步

- 所有结构化数据（文献、笔记、写作项目、音频脚本元数据）通过统一 `platform.library` 访问。
- 桌面：SQLite + 文件系统。
- 手机：本地数据库 + 可选云同步。
- 扩展：IndexedDB（过渡期）。
- 原 PDF、音频文件、导出 LaTeX 包按平台存储策略处理。
- 云同步（原 F10）作为可选能力，密钥与敏感内容由用户控制。

#### 11.0 v1：文字层原序（浏览器扩展，小范围朋友试用）

Wisdom 2026-10-28 15:00 定，这是 v1 的官方行为。

浏览器扩展按 PDF 文字层抽出的顺序翻译，不重排。源阅读顺序是 A B C D，抽出成 A C B D，译文就保持 A C B D。读者对照左边原文。朋友试用就按这个来。

这和 #189 拆分之后的 main 默认路径一致：整页多模态换页旗标默认关，顺序不来自页面模型。main 到 `4c3e839`（#191）为止，代码仍是 #190 的 `e8a6467`，#191 只同步了文档。这条旗标在 main 上还没有。旗标关着时不发整页多模态请求。

20:25 写过「v1 带上算法排序，常见版式大约 80%–90%」。15:00 起，那条不再是 v1 的官方行为。80%–90% 是当时的口径，本仓库没有另一份分数表。

main 上的文字层引擎还留着 #178 的按栏重排：`textLayerToBlocks` 在有作者行时走 `readingOrderLines`，正文页在检出双栏缝、且两侧都像散文时走 `orderLinesInColumns`。这两处会改掉抽出顺序。15:00 的官方行为是连这一步也不做。这次只记决定，不改代码。

`blocks` 数组的顺序仍是阅读顺序。渲染器和翻译器不要再按 y 排一遍。v1 里，这个数组就是文字层抽出的顺序。

#### 11.1 两档：版面跑在桌面，不跑在浏览器

Wisdom 2026-10-28 15:02 定。浏览器扩展继续给小范围试用，保持 11.0，不加载版面模型。版面分析在桌面应用上做（F11）。两档：

1. **默认。** 与 v1 相同：文字层原序，不重排。
2. **可选「智能版式」。** 用户自己打开。给多栏用，例如 Lancet、NEJM 这类医学期刊。关掉就是默认档。

「智能版式」打开时：

1. 本机 **PP-DocLayoutV2** 吃这一页的渲染图，给出区域、类别和顺序。检测在桌面本机完成，不把整页送去云端决定版面。结构、许可证和 81.4 这个数的范围见调研。权重、进程和安装方式这里不定，这次不加代码。
2. 文字仍来自 PDF 文字层，按位置映射进这些区域。不用 OCR 正文替换文字层。
3. 页眉、页脚、页码、图、图注、脚注移出主文流。
4. 主文流做两两续接检查：字体、标点、大小写、连字符。
5. Kimi 只在续接打平时，从 2–3 个候选里选一个。不把整页交给模型重排。
6. 检测失败、映射不上或置信不够：回到这一页的文字层顺序。这一页不能是空白。

22:03 禁止的是用 kimi-k3 做整页排序（决策记录：约 1.5 万–3 万推理 token，一页 5–10 分钟）。15:02 没有把整页排序加回来。20:25 里「LLM 只排序」、22:03 里「改用 glm-5.3-flash 或 deepseek-v4.1-flash-economy 排整页」到此为止，收成上面第 5 步。

#189 默认开启的「整页截图 → 模型直接吐出 blocks」仍是另一条，14:34 起默认关。

`pdf/high-precision/README.md` 里的 `PaddlePaddle/PP-DocLayoutV3_safetensors` 是更早的划区 sidecar 示例路径。智谱 GLM-OCR 的开源管线用的是 PP-DocLayout-V3，见调研。本方案选定的是 PP-DocLayoutV2，两套都还没接到阅读器上。

**公布的精度不够拿来当阅读顺序。** 百度在版面分析页给出 PP-DocLayoutV2 的版面检测 mAP(0.5) = 81.4，模型约 204MB（表内 203.8 MB）。同一张表写明这只是检测精度。页面上没有阅读顺序准确率，也没有 Lancet、NEJM 或其它医学期刊的数字。3 栏及以上必须用我们自己的评测，不能用 81.4 代替。评测还没做，这里不填通过率。

评测集合：

- 8–10 篇有 LaTeX 源的 arXiv 论文，源顺序当真值。
- 手标的 Lancet 等医学期刊。
- 按单栏、双栏、3 栏及以上分层。
- 要有跨栏图，也要有跨页续写。

#### 11.2 稳定块号来自版面，存在 core/

「智能版式」打开时，块号在版面落定时生成，跟着这一页的版面走，存在 `core/`（架构 v1.1 预留的目录；这次不建目录，不改代码）。换页、重开、翻译都不另盖一套临时页 id。

默认档没有版面模型。块号跟着这一页的文字层，不另造一套版面 id。

#189 里见过的反例（出处在复盘，这里只点机制）：stamp 前的临时 id（测试里的 `p3-b6`）和 stamp 后的稳定 bid（`b1-p3-m…`）不是同一个键；旧译文挂在别名上；后来又试过把旧 bid 绑回新块，再撤回。版面没变，块号就不变。版面变了，走 11.3，这一页作废，不靠别名把旧译文糊到新块上。

#### 11.3 按页作废

版面变了（检测版本、用户打开或关掉「智能版式」、或用户强制重跑这一页）：丢掉**这一页**的版面缓存和**这一页**的译文，按新块重译。笔记不动。默认档没有版面缓存可作废，译文仍按这一页的文字层块走。

这是 2026-10-28 12:14 对多模态换页定的规则。v2 把它收成「版面变化」的一般规则。作废范围是这一页的版面和译文，不是整库，也不是笔记。

#189 真机里，重建前后笔记正文的校验没有变（ff99b28、0007dbb，Anvil 报告）。锚点能不能重新对上，取决于这一页重开后还有没有块；0007dbb 上 Attention 第 2 页是空的，锚点没有对上。那是页上没有块，不是笔记被删。

#### 11.4 版面、块号、译文只有一处真相

一页的版面、块号、译文存在同一条记录里。打开时只认这一条。`core/` 是这块记录的去处，不是另开一张表再和文献库句对对撞。

#189 同时拿这些来源画同一页：文字层块、结构槽、文献库里的句对、不含 `kind` 的多模态缓存。缓存没有 `kind` 时，阅读区改画旧句对，类别会全部变成正文（ff99b28 的提交说明；cbb3a65 真机上重开后的 label 全是 text）。缺一个字段不能被解释成「去另一张表把整页换掉」。

#### 11.5 回退要写成明确状态，重开结果要确定

每一页在存储里带状态，至少分开这三种：

- 智能版式：有版面块，可以译。
- 回退：文字层原序。写明原因（检测失败、映射不上、置信不够、用户没开智能版式、parse、timeout、未配置之一）。块还在。
- 未开始。

回退页重开必须画出当时声明的那些块，顺序是文字层原序。不能把「没有块的多模态行」当成缓存命中，也不能画出空白页。0007dbb 的提交想修这件事；同一轮真机上 Attention 第 2、6 页和 DPO 第 2 页重开仍是 0 块，也没有文字层。所以「不留空白」是验收，不是已经在 main 上的行为。main 到 `e8a6467`（#190）为止没有这条旗标，#189 也还没合入。

旗标关闭时不发多模态请求。打开旧库的结果，和这一版文字层路径的新打开一致。不因为库里留着多模态行就去排队。

#### 11.6 验收

1. 用旧文献库数据重开，和同一份数据的第一次打开相比：块号、类别、顺序、译文有没有落地，都一致。
2. 回退页不是空白。重开仍能看到该状态声明的块。失败时顺序回到文字层原序。
3. 旗标关闭时，多模态请求数是 0。诊断里不能出现整页视觉请求。浏览器扩展的默认路径不加载 PP-DocLayoutV2。
4. 「智能版式」的 3 栏及以上，要先过 11.1 的评测再当可用。81.4 的检测 mAP 不能代替这一条。

前三条对着 #189 真机上没稳住的事：重开和首开不一致、回退后重开空白、默认路径会发多模态。旗标关闭是 14:34 的 v1 / v2 边界。合成夹具全绿不算过，见复盘。第 4 条是 15:02 加上的，评测还没跑。
