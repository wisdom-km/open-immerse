## pdf.js API

公开：`getDocument({ data, disableFontFace, verbosity, isOffscreenCanvasSupported })`、`PDFDocumentProxy.getPage`、`PDFPageProxy.getViewport` / `getTextContent` / `getOperatorList` / `render({ canvasContext, viewport })`、`GlobalWorkerOptions.workerSrc`。`disableFontFace` 是公开的 `getDocument` 选项。

`page.commonObjs` 是 `PDFPageProxy` 上已有的 getter，公开教程不列它。本仓库 `lib/pdf-mirror.js` 的 `attachFontRealNames` 已经在用。M0 复用该函数做字形归属，没有新增对它的私有调用，也没有调用 `CanvasGraphics` 私有方法，没有改 `pdf/vendor`。

## 开口风险

- FontFace 与 `disableFontFace` 轮廓的亮度差仍然大（门禁 max 约 61–161，mean 约 5–11）。缺墨为 0 只说明覆盖，不是逐像素一致。
- 12 个非门禁公式仍缺笔画（分式、`−∞`、部分上下标）。`svgVsOutlineMissing > 0` 表示选择器丢掉了轮廓里有的墨。
- 管线框经常比根号横线更窄。直线笔画会裁进公式框外扩 2pt 的矩形；框外的横线尖不会被补回来。拆开的公式（`p4-b14`/`p4-b15`）要等 M2。
- 发宽在 scale 1 记录，pdf.js 会把发丝线抬到约 1 设备像素。没有按缩放重描。
- 公式若真依赖 `paintImageXObject` 位图，当前 SVG 会缺墨。这批门禁没有。
- `fillText` 会计入 unsupported，不会画成假矩形。这几页次数为 0。
- 完全包住元素 bbox 的 clip 会丢掉；切开字形的 clip 会保留。门禁上没有因此失败。

## GATE 1

**GO。** G-a、G-b、G-c 在三个缩放下满足 M0-1 与 M0-2。M0-6 为 0。M0-5 有单测。M0-3 的差是边缘亮度，SVG 与轮廓缺墨为 0。非门禁残留留给 M2，不构成否决。
