# M0 向量公式 SVG 探针（GATE 1）

基线 `main@1d467b3ed944eb3c922ebd48a39698e0d8abeb96`。分支 `feature/v1-m0-vector-svg`。横线长度修复 `e288cd4`。字形选择 `13911f2` 与 `bceb629`。pdf.js `4.10.38`（`pdf/vendor` 未改）。未接分类器、阅读器 UI 或翻译。

## 结论

**GO。** 横线长度保持真机复查的结果（SVG/左栏约 0.93–1.07，短线只差 ±1px，不再伸进 `)V`）。根号、求和、大括号和公式逗号按字体或公式文本行留在 SVG 里。相对 `20487d4` 删掉的 281 个字形全部是正文行。命名案例在联合缺墨上实心为 0。240 份公式 SVG 都非空，正文计数为 0。

## P0-1 原因

pdf.js 4.10.38 的 `rescaleAndStroke` 在路径已经 `moveTo`/`lineTo` 之后才 `ctx.scale(scaleX, scaleY)`，把细于 1 设备像素的线宽抬到 1px。Canvas 规范是在坐标进入当前路径时套用 CTM，之后的 scale 只改变线宽，不移动已有点。录制器原先把 CTM 留到 `stroke` 时才烘焙，于是这次为了加粗而做的缩放（线宽约 0.4 时约为 2.5）把横线拉长了约 2.5 倍，同时线宽记成 1，和真机看到的一致。

修复：`moveTo`/`lineTo`/`bezierCurveTo`/`quadraticCurveTo` 在入路径时就变换到画布坐标。`Path2D`（字形轮廓）仍在 `fill`/`stroke` 时按当前 CTM 变换，因为 Path2D 自己不带画布矩阵。线宽仍按描边当时的 CTM 缩放到设备像素。

## 字形选择

保留：公式文本行里的字形（含 CMR 的 `softmax`、公式逗号、式号）、数学字体且墨与公式相交的字形（CMEX/CMSY/CMMI，含伸出行带的根号、求和和大括号）、墨盖住公式字形簇的字形。丢掉：文本行是正文字体且不是公式成员的字形。高算符的中心可以落在管线框外面，只要它的字体或文本行属于这个公式。

`e17e102` 用行带和中心点做排除，把根号、求和、括号和逗号一起删了。G-b 在 200% 的实心缺墨 25 是这些被删掉的括号，不是发丝线栅格。

## 容差

联合缺墨：左栏裁切与 SVG 范围的并集上，参考亮度 `< 160` 且半径 1 内没有 SVG 亮度 `< 210`。正文行字形的框（再外扩 2px）以及不与公式字形框相交的未选字形，不计入缺墨，这样上一行下伸部不会把丢了的根号掩盖掉。越界仍是 SVG 亮度 `< 160` 且半径 1 内左栏没有墨。元素 bbox 不是允许区域。

实心阈值亮度 `< 96`。96–160 是灰边。`INK_AA_TOLERANCE` 写明这四项。

正文计数 `bodyGlyphs` 统计留在 SVG 里、字体是 Nimbus/Times 等正文字体且文本行不是公式成员的字形，或已被标成正文行的字形。三条已知渗漏（G-b 上一行 `by` 的 `y`、Attention `p4-b6` 的 `n`、`p4-b19` 的 `ne`）现在都是正文行删除，计数为 0。
