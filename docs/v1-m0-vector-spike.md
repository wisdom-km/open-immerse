# M0 向量公式 SVG 探针（GATE 1）

基线 `main@1d467b3ed944eb3c922ebd48a39698e0d8abeb96`。分支 `feature/v1-m0-vector-svg`。pdf.js `4.10.38`（`pdf/vendor` 未改）。未接分类器、阅读器 UI 或翻译。

## 结论

**GO。** 横线长度和邻行渗入已按真机复查修好。分式线、根号横线与左栏墨长在 1px 以内（短线相对误差偶发略超 5%，绝对差仍是 1px）。全部 240 行的公式 SVG 里，正文邻行字形数为 0。

## P0-1 原因

pdf.js 4.10.38 的 `rescaleAndStroke` 在路径已经 `moveTo`/`lineTo` 之后才 `ctx.scale(scaleX, scaleY)`，把细于 1 设备像素的线宽抬到 1px。Canvas 规范是在坐标进入当前路径时套用 CTM，之后的 scale 只改变线宽，不移动已有点。录制器原先把 CTM 留到 `stroke` 时才烘焙，于是这次为了加粗而做的缩放（线宽约 0.4 时约为 2.5）把横线拉长了约 2.5 倍，同时线宽记成 1，和真机看到的一致。

修复：`moveTo`/`lineTo`/`bezierCurveTo`/`quadraticCurveTo` 在入路径时就变换到画布坐标。`Path2D`（字形轮廓）仍在 `fill`/`stroke` 时按当前 CTM 变换，因为 Path2D 自己不带画布矩阵。线宽仍按描边当时的 CTM 缩放到设备像素。

## 容差

半径 r=1。左栏缺墨：参考亮度 `< 160`，SVG 在半径内亮度 `< 210` 算盖住。越界：SVG 亮度 `< 160`，且半径 1 内左栏没有亮度 `< 160` 的像素。元素 bbox 不再当作允许区域。

实心阈值亮度 `< 96`：低于它的缺墨/越界是实心墨；96–160 是灰边抗锯齿，单独列出，不把灰边当成横线或邻行。`lib/formula-svg.js` 的 `INK_AA_TOLERANCE` 写明了这四项。

## 开口风险

- FontFace 与 `disableFontFace` 轮廓的灰边仍然对不上。100% 的实心缺墨为 0，但灰越界在 G-b 上仍有几十像素。这是字重/抗锯齿，不是邻行。
- scale 1 录制的 SVG 放大到 150/200% 后，和 pdf.js 当场重画的轮廓会差十几个到几十个实心像素。发丝线在每个缩放都被抬到约 1 设备像素，不会随 SVG 一起变粗。
- 字形必须大部分落在公式框里，且中心落在该公式自己的字形框上。只擦到框边的上一行不再进入 SVG。管线自己把正文收进字形框时，M0 不会把它拆出去。
- DDPM `p3-b20` 的框左缘切字是 M1 边界，不是这次的录制修复。
