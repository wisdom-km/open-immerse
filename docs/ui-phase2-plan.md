## 1. 七条反馈

### 1.1 加「笔记」和「问 AI」（照 easyread 演示）

**笔记**（批注和论文笔记）：

- 筛选：全部 / 我的笔记 / 划线 / AI / 待回答。
- 给当前段落写笔记（右栏当前读到的那一段）。
- 按原文页分组，每组标「原文第 N 页 · 章节名」，点组头跳到那一页。
- 每条可以：编辑、改成问题、删除（删除后能撤销）。
- 导出（Markdown）。
- 笔记存在本机。是否进本地库服务、怎么跟论文绑定（建议按 PDF sha256），等 Loom 规格和第 1.5 条一起定。

**问 AI**：

- 选中一段或一个公式，引用它来问。引用块里要看得出引的是哪一页、哪一段。
- 回答里的数学用 KaTeX 渲染。
- 回答能一键复制。
- 支持多轮追问，同一个会话里记得前面问过什么。
- 用插件已配置的大模型 API（OpenAI 兼容），不另加服务。
- 引用公式时送什么：有第零层（arXiv 源码，见 `docs/arxiv-source-mode.md`）就送核对过的 LaTeX；没有就送公式裁图给多模态模型（见 1.7）；都没有才送文字。界面上要写明「会把引用内容发给你配置的模型」。
- 不做「看一整页直接出中文」（REQUIREMENTS §2.3 仍然不做）。

**验收：**

- [ ] N1 五个筛选各自只显示对应的条目，计数和列表一致。
- [ ] N2 「给当前段落写笔记」挂到右栏当前段落；点笔记能跳回那一段，原文栏跟到同一位置。
- [ ] N3 编辑、改成问题、删除（含撤销）都能用；刷新或重开同一份 PDF 后笔记还在。
- [ ] N4 导出的 Markdown 按页分组，含引用原文和笔记内容。
- [ ] A1 选中段落或公式 →「问 AI」，引用块带页码；回答里的公式由 KaTeX 渲染，不出现裸 `$…$`。
- [ ] A2 复制按钮复制的是回答原文（含 LaTeX 源）。
- [ ] A3 连问三轮，第三轮能用到第一轮的上下文。

- [ ] A5 测试用 Attention 夹具和假的模型接口，不联网、不花钱。

### 1.2 中间分隔条和滚动条要细、要淡（参考 Readest）

Loom 已查清：Wisdom 看到的那条粗黑竖条**不是分隔条**，是原文栏 `#pages` 的系统滚动条。原因是 `ui/tokens.css:3` 写了 `color-scheme: dark`，阅读器没有覆盖，Chrome 就画出 15px 宽的深色滚动条。

按 Loom 规格分两步：

- **热修（只改 token）**：阅读器根加 `color-scheme: light`（写在阅读器自己的 token 文件里，不改 `ui/tokens.css`）；分隔条握把平时不显示（`--oi-reader-split-grip-opacity: 0.45 → 0`）。改完就没有黑条。要回归 Aa 面板里的原生控件。
- **后续（要改 CSS / JS）**：`::-webkit-scrollbar` 细滚动条（槽 10px、轨道透明、滑块 6px，悬停 10px，颜色取 ink 低透明度，1.2 秒自动隐藏）；握把悬停 120ms 后出现；拖动时线变蓝并显示「原文栏 42%」气泡；补 ARIA。
- **已定**：握把从「常显 45%」改成「只在悬停时出现」。这是 Wisdom 确认的方向（23:52），Loom 按这个做，热修不用再等。
- 还要 Forge 裁定的：槽宽变成 10px 后，SPEC §9 L2 的「起始侧 49–56」要改成 54–60。

**验收**（摘自 Loom 规格 §6）：

- [ ] SB1 四个主题 × 1440 并排，两栏滚动条都看不到深色轨道（截图取色，没有 #2C2C2C 一类深灰）。
- [ ] SB2 两栏滚动条槽宽都是 10px（后续那一步）。
- [ ] SB4 `#pages` 的 computed `scrollbar-color` 是 `auto`，阅读器里没有可继承的 `scrollbar-color`。
- [ ] DV1 分隔条静止时看不到握把；拖动时线是 focus 色，全页不能选字。
- [ ] 回归：Aa 面板的 checkbox、range 在浅色下正常；同步、版心、胶囊的现有测试全过。

### 1.5 右侧的论文库管理

- 列出打开过的论文（本地库）。
- 每篇能看、能打开、能删除它的译文和缓存数据（含第零层的 arXiv 源码缓存、笔记）。
- 依赖：本地库服务（`127.0.0.1:8765`）现在只有按 hash 取一篇（`GET /v1/library/document`）和存一页（`POST /v1/library/page`）。列表、删除要服务端加接口；服务端代码不在本仓库，要先确认谁来改。arXiv 源码缓存在扩展自己的 IndexedDB，不在本地库服务里（arXiv 决定 9），管理界面要分开显示、分开清。

### 1.6 译文栏左侧的「目录 / 术语 / 说明 / 最近」抽屉，和「见原文第 N 页」占位

### 1.7 模型也要支持多模态

Wisdom 原话：模型除了大语言模型，也要支持多模态。公式按技术路线逐级退：先多模态识别，再矢量重绘，再裁图，最后用占位。第二层（看图模型补公式）等 Wisdom 接上 API。

- **已定**：公式的逐级退顺序是「多模态识别 → 矢量重绘 → 裁图 → 占位」。2026-10-05 00:15 Wisdom 定：运行时顺序是 arXiv 源码 → 多模态 → 矢量重绘 → 裁图 → 占位；没接多模态 API 时从矢量重绘开始；层号不改。以下是文档细化，待确认：多模态要用户接上 API 并打开第二层开关才走，输出和 PDF 字符核对，对不上往下走；矢量重绘把握分数低、裁图不清楚或切到邻行就往下走；每一步都由程序自动判、不靠人看，门槛见 REQUIREMENTS §2.6「运行时顺序」（初始值，待实测）。占位按第 6 条是「图见原文第 N 页（点击查看）」，点了原文栏跳到原位并画框。行内公式：沿用 2026-10-02 规则（用优化裁图，不走看图模型），顺序为第零层 → 矢量重绘 → 裁图 → 占位；00:15 新顺序是否适用于行内，待 Wisdom 确认。
- **REQUIREMENTS 已同步（PR #98）**：REQUIREMENTS §2.6 改成上面的运行时顺序，ARCHITECTURE、EXECUTION、`docs/arxiv-source-mode.md` 同步。层号不改（第一层是矢量重绘和原页裁图，第二层是多模态，第三层是占位），运行时顺序和层号不同：第二层排在第一层之前。第二层开关默认关闭，DPO 79 个公式的实验做完、产品方决定上线之前保持关闭（Wisdom 原话「保持关闭」）。上线前是否在界面上隐藏这个开关，待 Wisdom 确认；若隐藏，「先多模态」实际要推迟到上线决定之后。（建议）开关开着时每个独立公式都会先送一次裁图，费用和隐私提示要在开关旁写明，具体以 Loom 规格为准。
- 模型设置里要能配一个多模态（能看图）的模型，可以和翻译模型分开配。
- 用到它的地方：问 AI 引用公式或图时送裁图（1.1）；公式逐级退里第零层之后的第一级（REQUIREMENTS §2.6 的第二层，等 Wisdom 接上 API）。
- 只送单个公式或单张图的裁图，不送整页（§2.3 不做整页看图出中文）。
