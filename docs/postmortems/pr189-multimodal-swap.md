## 4. 找到的根因

每一条先写能核对的出处，再写它没有单独被真机证明已经修好的地方。

### 4.1 块号重盖和别名

**证据。** `1379a65` 的 `formula-reopen-cache`：期望 `unitId` 是临时页 id `p3-b6`（`raw.id`），实际是 `b1-p3-m000p10r`。同一份报告写：存下的 bid 会作为 alias 留着；DPO 第 15 页的尾块既在主 bid 列表里，也作为另一块的 alias。`9e1c8f4` 只把测试锁改成稳定 bid（`/^b1-p\d+-m/`，且不等于 `raw.id`），Box 就过了。

**提交说明。** `9e1c8f4`：文字层在 stamp 之前已经算出和 `stampLayoutBids` 相同的公式 bid，临时页 id 不再当缓存键。`4510325`：结构译文从旧行 bid 改绑到换页后的整段。`cbb3a65`：不再把旧 bid 绑回新块。`ff99b28` 的注释写：写在 stamp 前那个 bid 上的 200，现在是 alias。`0007dbb` 把「画回旧块号」移出 `pdf-blocks.js`，并写明活块上的回声不能盖住 alias 上已经落地的译文。

**没有收口。** 真机从 `3efed2e` 到 `0007dbb`，摘要块 `b1-p1-t08yfuug` 一直是英文。改绑、解绑、再按 alias 画回，三轮都没让这个块变成中文。

### 4.2 结构槽去重丢掉摘要

**证据（提交 diff）。** `6d3bd59` 删掉的过滤是：和结构槽原文完全相同的块不再进入翻译；注释写明结构槽已经会译这份原文，只有「坐在更长槽里面」的块（点名 abstract paragraph、footnote）才单独存。提交说明把修法写成：多模态页不画标题壳，和结构槽原文相同的块仍要按新 bid 翻译。

**没有收口。** 下一轮 `6d3bd59` 的真机摘要仍是英文，多模态只发出 1 次。报告把「修法没有写到新 bid」标成推测。现象是证据，机制是否仍是这条过滤，报告没有在真机上再证一次。

### 4.3 `writeStoredLayout` 占着飞行槽

**证据（提交 diff）。** `6d3bd59` 把 `writeStoredLayout` 挪到飞行槽释放之后。注释原文：一次永不返回的写入会让第 2、11、12 页停在「正在重建本页」，后面不再发视觉请求。

**现象。** 该轮真机就是这三页停到 300 秒，期间没有新的多模态请求。报告没有把「释放之后写入仍占着槽」证成事实，相反把「先释放槽位没有生效」放在推测里：卡住的可能是旧缓存走了另一条路，根本没进飞行队列。

### 4.4 页栅格的 promise 不返回，`Promise.race` 忽略 thenable

**提交说明。** `4510325`：`6d3bd59` 放开布局写入之后，第 11 页已经打出 `mm.page.start`，但 `page.render()` 的 promise 可以一直不返回，飞行槽停在发请求之前。

**证据（`cbb3a65` 的 `lib/render-deadline.js` 注释）。** 「`Promise.race` is the wrong tool here. If the render promise fulfills with a thenable, the race locks onto that thenable and ignores the timeout.」这一轮改成包装器自己计时，到点拒绝。

**现象。** `4510325` 真机：卡住的页显示的是「正在重建本页」，0 页出现「已改用文字层 · 超时」。8 秒截止没有落在这些页上。这和「超时没有赢得等待」相符。注释里的 thenable 机制没有在真机堆栈里再看到一次，本文把它记成提交里的机制说明。

### 4.5 重建条在错误的栏里被清掉

**证据（`ff99b28` 的 `pdf/viewer.js` 注释）。** 阅读区在 `#readerFlow`。`#pages` 是 PDF 栏，里面没有 `.rf-page`。回退或丢掉的任务以前去 PDF 栏里找块，状态清了，阅读区的「正在重建本页」还在。

**现象。** `ff99b28` 真机：Attention 15 页的重建条都消失了。`0007dbb` 又有第 10–15 页停到 300 秒。所以「清错栏」对得上 `ff99b28` 之前清不掉的条。它解释不了 `0007dbb` 后半本又停住。报告把后半本停住归到推测：回声重发拖慢了后面的页。

### 4.6 多模态缓存丢掉 `kind`

**提交说明。** `ff99b28`：多模态页重新打开时缓存没有 `kind`，阅读区改画了旧句对。

**证据（同一提交的注释）。** 版面缓存里的多模态页不带 `kind`。若因此落到文献库句对，每个 label 都会画成 text。`libraryPairsReplaceLayout` 在 `mode === "mm-page"` 或 `pagePipeline === "mp-1"` 时不再换页。

**现象。** `cbb3a65` 真机：重开后 TXL、DPO 的 label 全是 text，块也比首开少。`ff99b28` 上 DPO 重开的种类和首开一致，TXL 第 1 页一致，第 2 页是 0 块。类别保住了的页和空白页同时存在，不能写成「kind 一修，重开就对了」。

### 4.7 回退页被当成缓存命中

**提交说明。** `0007dbb`：解析或覆盖率回退的页，不再被没有块的多模态缓存当成命中。diff 里 `mmLayoutCacheHit` 对 `fallback` 和空块返回 false；`reopenFallbackLayout` 在不是命中时画回文字层块。

**现象。** `ff99b28` 真机：TXL 第 2 页首开是「结果无法读取」的文字层回退，重开 0 块。报告的推测是回退被当成命中、却没有块可画。`0007dbb` 真机：Attention 第 2、6 页和 DPO 第 2 页重开仍是 0 块，也没有文字层。报告的推断是：不再把回退算成命中之后，重开没有补画文字层。推断不是证据。空白页是证据。

### 4.8 回声译文被当成已经译完

**提交说明。** `0007dbb`：与英文原文相同的旧译文不再算已译，也不能盖住后来的译文。注释写：空文本不是回声；回声不能让新块看起来已经落地，也不能覆盖后来的 200。

**现象。** `26970d7` 真机摘要是「旧译文未沿用」加英文原文，当次翻译请求数是 0。从 `3efed2e` 起每次都有 200 的翻译请求，摘要块仍是那句英文 "The dominant sequence transduction models…"。main 并排时同一摘要是中文。请求打到了哪一个 bid，报告标成推测，没有在日志里对上响应正文。

### 4.9 版面修订号被带高的风险

**证据。** `ff99b28` 改了 `lib/pdf-blocks.js`。报告写这个文件是版本哈希的 4 个输入之一，锁定值没有跟着重算。实测 tip 为 `source-v3:63737d2e9d8c3216`，锁定为 `source-v3:1d5f1ca0ee90cec1`。只在 tip 上失败，main 通过。报告写的后果：设备上已存的 source-v3 文字层缓存都会被当成过期。

**提交说明。** `0007dbb`：把多模态画回旧块号的逻辑移出 `pdf-blocks.js`，避免把每个用户的文字层缓存标成过期。Box 上 `pdf-layout-revision` 通过，锁定值回到 `source-v3:1d5f1ca0ee90cec1`。

这条哈希没有进 main（#189 未合）。风险停在那条未合分支的 `ff99b28` 上；`0007dbb` 的 Box 把哈希测回锁定值。用户库是否真的整库失效，没有在 `ff99b28` 的真机里单独测，报告写的是哈希变化本身。

## 5. 为什么没有收敛

两件事叠在一起。都有报告里的对照，不是事后另编的故事。

**合成夹具和真库不是同一状态。** `26970d7` 报告写 Lancet 标题在文字层仍拆成 3 块，和 main 一样，Box 单测用的是合成数据。`3efed2e` 报告写 Box 全绿、真机失败，单测没有覆盖「库里已有译文，再做一次真实换页」。`6d3bd59` 报告写新测试是合成数据，没有这条路径。`4510325` 起 Box 里有「重开后摘要有译文」的用例，单独重跑可以过，真机上同一个摘要仍然是英文。夹具能构造一块新的摘要；它没有带上那份真库里的旧句对、旧版面和已经写成英文的占位。

**在会变的块号上搬旧数据。** 临时 id、stamp 后的 bid、alias、结构槽、文献库句对，每一轮都在这几套号之间搬译文：先改绑（`4510325`），再禁止绑回（`cbb3a65`），再把旧号上的 200 画回当前块（`ff99b28`），再声明回声不算完成（`0007dbb`）。块号在换页时变，旧库的键不变。搬完一轮，下一轮真机仍指着 `b1-p1-t08yfuug` 那句英文。到 `0007dbb`，重开还出现了首开时有块、重开时 0 块的页。

v2 因此不在这条路上继续打补丁。版面先定，块号从版面来，变了就按页丢掉缓存和译文。见 [`docs/architecture-redesign.md`](../architecture-redesign.md) 第 11 节。

## 6. 过程教训

**先用真状态的夹具复现，再改。** 每一轮都是 Box 先绿（或只剩抖动），真机再在旧库上失败，下一提交修报告里的推测。`6d3bd59` 的「释放飞行槽」、`4510325` 的「改绑旧 bid」都是这样上去的，下一轮真机原句还在。以后修换页：诊断包里的页状态、块号和缓存行先做成夹具，夹具不过就不改产品。合成的「新打开一份 PDF」不能代替「库里已经有这页」。
