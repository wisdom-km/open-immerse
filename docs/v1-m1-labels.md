# M1 标注：编号、预标注、复核

这一页给复核的人用。产品界面不在这里。需要 Node.js 20 或更新的版本。

## 语料

30 篇公式比较密的开放获取论文，6 个领域各 5 篇。清单在 `corpus/manifest.json`。PDF 不进 git。`git status` 在只多了本地 PDF 或 `tests/fixtures/DDPM_2006.11239.pdf` 时应当是空的：这两个路径都在 `.gitignore` 里。

经济学/金融是第 6 个领域。每个领域至少 3 篇出版社排版的开放获取 PDF。人工智能保留 Attention 和 DDPM 两篇 arXiv，另外 3 篇是 Nature Communications。定量生物学 5 篇都是 PLOS Computational Biology。医学 5 篇都是出版社排版：Scientific Reports 的药代和成像重建，加上 BMC Medical Research Methodology 的样条轨迹模型。物理是 Nature Communications、Communications Physics 和 JHEP。数学是 Scientific Reports 3 篇，加上 Forum of Mathematics Sigma 和 Comptes Rendus。经济是 Scientific Reports、PLOS ONE、Quantitative Economics，并保留一篇公式很密的 q-fin 预印本。Physical Review X、Wiley、IOP、PNAS、Royal Society 的直接 PDF 返回 403，这些站点已跳过，没有改请求头。公式印成图片的论文已剔除。清单里每篇都有许可证、PDF 直链和原因。没有 Word 导出的 PDF。

来源分三种：

- `publisher-typeset`：出版社排版，例如 Nature Communications、PLOS。
- `author-latex-journal`：期刊的正式版本，文件仍是作者 LaTeX，例如 JMLR、Forum of Mathematics Sigma、JHEP、Quantitative Economics。
- `author-latex-preprint`：arXiv 预印本。

安装依赖并下载。用 `npm ci`，不要用 `npm install`（后者会改写锁文件）：

```
npm ci
node scripts/corpus-fetch.mjs
```

核对用的是内容指纹 `contentFingerprint`，不是字节 SHA-256。指纹是 pdf.js 抽出的每页文字（字符串和文本矩阵，坐标保留两位小数）、页数、页面宽高和旋转角的 SHA-256。Info 字典、XMP 和文件尾的 `/ID` 不参与。Cambridge 的 Forum of Mathematics Sigma（`fms-2021-7`）还会在每一页正文里印一行 `Downloaded from … IP address …, on <日期> at <时间>`。这一行的 IP 和时刻每次下载都变，所以计算指纹前会整行丢掉，预标注写 JSON 时也不留下这一行。匹配式是 `^Downloaded from … IP address`，必须两头都有，普通句子里的 “Downloaded from” 会留下。丢掉之后，`fms-2021-7` 的内容指纹可以和清单对上。字节哈希仍然对不上，清单里的 `sha256` 只记录某一次下载，脚本打印它，但不拿它判断成败。

脚本不会在第一篇失败时停。每篇结束都会留下一行，最后打印表，状态是 `ok`、`hash-mismatch`、`blocked-by-challenge`、`network-error`，或在 `--import` 时多一个 `skipped`。只有结束时还有失败，退出码才不是 0。`--import` 目录里提供的文件只要有一份没通过核对，退出码就不是 0。目录里没有的篇目记为跳过，这时退出码仍可以是 0，这不表示语料已经齐。短暂的网络错误会退避重试几次。出版商的机器人检查不会重试，也不会用伪装的请求头、Cookie 或无头浏览器绕过。

Springer Nature、BMC、JHEP 在有的网络上会跳到 `idp.nature.com` 或 `idp.springer.com`，返回大约 3 KB 的 Client Challenge 网页。表里的说明是中文：出版商的机器人检查拦住了这次下载，请用浏览器手动保存 PDF，再用 `--import` 导入。

手动补文件：

1. 用浏览器打开 `corpus/manifest.json` 里该篇的 `url`。
2. 把 PDF 保存为 `corpus/pdfs/<id>.pdf`。`id` 就是清单里的 `id`，例如 `s41467-018-07210-0.pdf`。
3. 再运行 `node scripts/corpus-fetch.mjs`。已经在 `corpus/pdfs/` 里、并且内容指纹相符的文件会直接通过，不再下载。`fms-2021-7` 也按内容指纹核对；水印那一行不参与。

如果 PDF 在浏览器的下载目录里，而不是仓库里：

```
node scripts/corpus-fetch.mjs --import <目录>
```

`--import` 只导入这个目录里已有的 `<id>.pdf`。它先核对内容指纹，再复制到 `corpus/pdfs/`。指纹不符、不是 PDF、或是出版商的检查页，都不会复制，并且这次运行的退出码不是 0。目录里没有的篇目会记为跳过，不会重新下载；只跳过、没有核对失败时退出码是 0，这不表示语料已经齐。

`tests/fixtures/DDPM_2006.11239.pdf` 如果已经在磁盘上，并且内容指纹和清单里的 `2006.11239` 一致，就直接用它，不必再下一次。

## 元素编号

每一页的每个文字项、没有对上文字的笔画、矢量路径和图片都有一个 id。id 只由这几项决定：种类、完整字符串、字体名、量化到 0.01 的框、路径哈希、以及同一指纹在本页里的序号。

文字项的 `char` 是 pdf.js 给出的整段，不会从一段里按比例切出一个字母。路径的 `char` 和 `font` 必须是空的。把「i」写到根号的框上，id 会对不上，`verifyPageLabels` 会失败。

预标注文件在 `labels/prelabel/`，复核集是按这批预标注生成的。复核前不要再跑 `node scripts/corpus-prelabel.mjs`。重跑会改单元编号，和 `labels/review-set.json` 对不上。只有预标注规则再变时，才需要 `--force` 重跑，并重新生成复核集。

## 预标注规则

这些是机器规则，不是人工判断标准。人工标准在下一节。

- 数学字体，或 NewTX、Fourier、TeX CM 这类补充字体：公式，置信度 0.96。
- 数学 Unicode：公式，0.90。
- 等宽字体：代码，0.90。
- 更小、并且基线相对紧挨着的前一个基字母上移或下移的上下标，并进那个基字母，合成一个单元。新接上的上下标没有单独的正确率信号，置信度是常数 0.55（`script-attached`），基字母若原本不是数学字体或 `script-offset`，也记 0.55（`script-base`）。这两项都低于 0.65，所以会计入 A4。旁边已经按「更小、有偏移、紧挨数学」判过的，仍用 0.82（`script-offset`）。不抬到 0.96。
- 同一行上紧挨着公式的运算符、括号和数字并进该公式。粘合段 `math-run` 的置信度是常数 0.50，没有单独的正确率信号，低于 0.65，会计入 A4。短分数线仍是 0.80。
- 预标注不跨行合并。上下限若落在另一行，不会并进求和号。成员数不少于 60 的行内单元，置信度压到不超过 0.55。
- 正文词或标点正后方的小号上移数字（含逗号、短横、*、†、‡），行首脚注号，☯，以及和本页参考文献编号相同的这类上标：文字，不是公式。置信度 0.84（`citation-or-footnote`）。表脚下单独的 `a`、`b`、`c`、`*`，后面跟着说明文字的，也是文字（`table-note`）。`x_i`、`a^4`、`k_a` 这种紧贴短符号的指数仍是公式。
- 没有基字母、只是单独漂着的弱上下标：公式，0.62，会进复核队列。
- 其余正文：文字，0.93。
- 很长的横线或竖线（表格线、图的边线）：其他（`rule-line`）。插图里的矢量路径不标成公式。短的分数线，挨着同一行的公式时，仍是公式。图片：其他。
- 行末、靠右、形如 `(12)` 的正文，并和公式同一行：公式编号，并进那个行间单元。
- 单元置信度是成员里的最低值。低于 0.65 记为 fallback，复核时优先看。A4 量的就是这个自报置信度，不是准确率。置信度不会为了少进队列而被抬高；0.55 和 0.50 是故意落在 0.65 下面的。

算法环境如果用的是正文字体，预标注仍标成文字。需要的话在复核里改成「其他」。

## 复核判定标准

一个公式单元是读者会当成同一个式子的那一组字形。

算进同一个单元：

- 基字母和它的上下标。`k_a` 是一个单元，不要只留下下标 `a`。`P_Ω^L`、`E_hb`、`β_T = 0.02` 也是整段一个单元。
- 行间公式的全部行，包括分数线、根号、大的求和号 `∑`。不要把左半和右半拆开。
- 括号、运算符和它们包住的式子，中间没有正文的时候放在一起。
- 行末单独的 `(1)`、`(2.3)` 这类公式编号，并进它旁边的那个行间单元。

不算公式。按下面的键改：

| 看到的东西 | 按键 |
| --- | --- |
| 脚注号、引用上标、作者单位上标、节标题、整行正文、图注里的整句、带单位的量（例如 `50 μm`） | `2` 正文 |
| 插图里的坐标、刻度、矢量路径，表格线，图注和正文之间的分隔线 | `4` 其他 |
| 脚注符号 ☯，表脚下的 `a`、`b`、`*` | `2` 正文 |

- 脚注号，例如页边上的小 `4`、`16`。复核集打开后如果第一条是这种脚注号，按 `2` 改成正文，再按 Enter。
- 引用上标，例如 `17`，以及表格里的 `[23]`。
- 作者单位上标 `1`、`2`。
- 节标题，例如 `B.2`。
- 整行正文被标成公式时，按 `2`。
- 图注里的整句说明，以及 `50 μm` 这种量加单位，按 `2`。

行内单个变量，例如句子里的 `x` 或 `λ`，如果它在当数学符号用，标成行内公式。普通英文单词不要标成公式。

写在正文或表格格子里、用逗号隔开的一串数学符号，例如 `tau_rise, tau_decay, tau_syn, G, E_syn`，每个符号单独是一个行内单元，不是整串一个单元。每个符号自己的下标留在这个单元里。框住其中一个符号再按 `s`，这一部分会拆成新的行内单元，其余的留在原来的单元里。

括号里写成的元组或向量是一个行内单元，例如 `(u_0i, u_1i)`、`(beta_0, beta_1)`、`(k_1, ..., k_m)`、`(d, m) = (3, 2)`。符号、各自的下标，以及中间的逗号，都属于这一个单元。括号如果是单独的字形，就把括号也放进这个单元。括号如果已经嵌在更宽的正文里，例如正文元素 `and random effects (`，这段正文保持正文。这时单元里没有这对括号，也是对的。每个符号单独成一个单元，只用于没有外层括号、写在正文或表格格子里的一串符号，例如 `Parameters: tau_rise, tau_decay, tau_syn, G, E_syn`。

行间公式同一行末尾的逗号或句号属于这个行间单元，要留在公式里，因为导出的公式图会带上它。复核时把这个标点和公式一起框住再按 `m`，它会留在行间单元里，不会被当成宽正文拒绝。行内公式后面的逗号或句号是句子的标点，保持正文，不要并进公式。

正例：`k_a` 整组一个单元；行间式和右侧 `(1)` 在同一个单元；`β_T = 0.02` 整段一个行内单元；`(u_0i, u_1i)` 这整个元组是一个行内单元。

反例：只框住下标 `a`；引用上标 `17` 被标成公式；两个不相干的式子并成一个单元；一个行间式被拆成左右两截；节标题或脚注号被标成行间公式。

## 标点和括号怎么标

| 看到的情况 | 标成 | 例子 |
| --- | --- | --- |
| 公式内部的逗号，用在参数之间、下标之间、元组各项之间，或写在括号里 | 公式 | `(u_0i, u_1i)`，`H^{m,p}`，`f(S, delta, t)` |
| 没有外层括号，写在正文或表格格子里，用来隔开一串独立符号的逗号 | 正文。每个符号自己是一个行内单元 | `q_x, q_y - the heat flux components`，`Parameters: tau_rise, tau_decay` |
| 行内公式后面、分句或句子末尾的逗号或句号 | 正文 | `SVX_I.` |
| 行间公式那一行末尾的逗号或句号 | 公式，并进同一个行间单元 | 行间式末尾的逗号或句号。同一行两个式子各有一个逗号时，两个逗号都留在这一个行间单元里，例如 `σ′xx = σxx + γθ,  σ′yy = σyy + γθ,` |
| 属于数学的括号，例如元组、用数学字体写的函数参数、区间 `[0, T]`。这些括号是单独的字形 | 公式 | `(u_0i, u_1i)`，`[0, T]` |
| 属于名称或正文的括号，例如 `ADAPT(eps_3)`，`Cov[` 落在正文块里的 `Cov[...]`，以及引用括号 `[12]` | 正文。只框里面的数学 | `ADAPT(eps_3)` 只框 `eps_3`。表头里的 `ADAPT(ε₃)` 也一样，单元只有 `ε` 和 `3`，`)` 是正文 |
| 括号或标点粘在更宽的正文块里，这块正文里还有普通单词 | 这段正文保持正文。单元里没有它也算对 | `and random effects (` |
| 标点粘在数学字符上，合在一个没有普通单词的短元素里 | 公式。把这个元素并进公式单元，跟着进来的标点可以留下 | `q > 0:` 里的 `0:`，`Δ ≥ 0, q > 0` 里的 `0,` |

标点如果和数学字符粘在同一个没有普通单词的短元素里，就把这个元素放进公式单元，因为去掉它会丢掉那个数学字符，跟着进来的标点可以留下，这和标点粘在带普通单词的正文里相反，那种正文保持正文。

拿不准时先问拿掉这个记号数学会不会变：会变就是公式，只影响句子就是正文。

## 复核经验总结（常见情况）

### 什么算一个单元

一整条公式是一个单元。下标、上标、分数线、根号、括号和公式编号都是它的成员，不要先一层一层合并。数学扩展字体里的大括号、方括号和 `∑` 会显示成字形框加上它下面的墨迹，这些块都是公式成员，见「空框」。同一行并排的两个行间式是一个行间单元，两个式子末尾的逗号都留在这个单元里。例如 `p_1^mu = ... , p_2^mu = ... (2.8)`，以及 s41598-022-19656-w 第 3 页居中的 `σ′xx = σxx + γθ,  σ′yy = σyy + γθ,`。出现在不同句子里的两个不相干的式子，各自是一个单元。

编号写在后面某一行时，这一轮按行复核。每一行自己是一个行间单元，不要跨行合并。例如上面那一页的下一行 `α = ..., β = ... (13)`。跨行归组是 M2 分类器的事。

### 行间还是行内

单独占一行、居中排的公式是行间式，有没有编号都一样，按 `d`。s41598-022-19656-w 第 3 页那一行自己没有编号，也按 `d`；下一行带 `(13)` 的同样按 `d`。写在句子里面的公式是行内式，按 `i`。

### 元组和符号清单

括号里的元组是一个行内单元。没有外层括号、写在正文或表格格子里的一串符号，每个符号自己是一个行内单元。逗号和括号的细节见「标点和括号怎么标」。

### 正文字体里的函数名和算子名

`sin`、`max`、`log`、`Cov`、`ppcm` 这类名字是公式的一部分。预标注把它们标成正文时，用 `m` 并进公式，后面有没有括号都一样。`Cov[` 如果嵌在带普通单词的正文里，例如 `Indeed, Cov[`，这段正文保持正文。

### 带括号的名称

`ADAPT(eps_3)` 这种名称，只把里面的数学标成公式。括号如果属于名称或正文，不要并进公式。表头里也一样：`ADAPT(ε₃)` 的单元只有 `ε` 和 `3`，`)` 是正文。

### 单位

正文字体的数字加单位是正文，例如 `50 μm`、`1 kcal/mol`。排成数学的单位是公式，例如带数学字体括号、斜线、分数或上标的 `(cells/mm^2)`。

### 句子里的单个斜体变量

句子里当数学符号用的单个斜体变量，例如 `x`、`t`、`q`，如果出现在队列里，标成行内公式。

### 空框

大算符 `∑`、`∫`、`∏`，以及数学扩展字体里的大括号、方括号，PDF 常把字形框记在墨迹上方。看得见的墨迹是另一个空字符元素。复核工具现在把这一对画成一个框，点选、拖选、加减选区、合并、拆开、公式编号和改标签都把它们当成一块。字形里有几个分隔符，就带上几块墨迹，例如 `{(` 下面的大括号和圆括号仍是一个框。这些元素仍各自留在数据里，标签和单元相同。右栏会把它们都列出来，并标明成对。按 Enter 确认时，如果当前单元里只有其中一块，会自动把另一块补进同一个单元。右栏可能多次列出「路径」，这没有关系。

### 看什么

只核对红色实心的单元，也就是队列里的 1000 条。灰色细框是其他预标注，不用管。同一页上不在队列里的灰色框可以不改，例如 s41467-019-10988-2 第 7 页的 `ADAPT(ε₁)`、`ADAPT(ε₂)`。为了前后一致去改它们，也没有害处。橙色虚线是你自己的选区，不是一个单元。灰色点线旁边带数字的，是这一页上另一个还在队列里的单元。后面队列里的一条可能已经并进前面的单元，例如 2006.11239 第 2 页队列第 127 条现在在公式 (3) 里面。轮到它时，红框是合并后的那个单元，核对一下再按 Enter。

### 操作

拖选要盖住元素的中心，并且大约六成面积也在框里。Shift 是追加。Ctrl 或 Cmd 点击是切换一个元素。按住 Alt 拖动是减去。`z` 放大当前红色单元，再按一次回到原来的缩放。`m` 合并。合并之后看右栏的元素个数。`s` 拆开时只选中要拆出去的那一部分。只选中一部分再按 `s`，没选中的成员会变成另一个单元。2006.11239 第 2 页公式 (3) 里，下标和上下限就是这样被拆出去的。把整行选中再按 `m` 就能合回去。单独成一个单元的大号 CMEX `[`、`]`、`∑` 也属于这个公式。如果把整个单元都选中再按 `s`，每个字形会拆开，再把这些字形选中按 `m` 就能合回去。`e` 标公式编号。`2` 是正文，`4` 是其他。`d` 是行间，`i` 是行内。`m` 被拒绝时，看右栏的红字，把列出的正文从选区去掉，再试一次。被拒绝的选区按 Enter 不会记成已复核。对已经复核过的单元再按 Enter，会覆盖上一次确认，计数不会加两次。用 `j` 或 `k` 可以跳过一个单元，不确认。

### 工具的已知限制

粘在正文块里的括号或标点不能单独选中。把这段正文留成正文，算对。这不是复核人的错。

## 复核

```
node scripts/label-review.mjs
```

用 Chrome 打开它打印的 `http://127.0.0.1:4173/`。这是给 Windows 上复核用的本地页，不是读者界面。

Ctrl+C 停止服务。端口被占用时，在 PowerShell 里换一个端口：

```
$env:PORT=4174; node scripts/label-review.mjs
```

- 颜色：整页队列里公式按单元分色，正文灰，代码绿，其他橙。置信度低于 0.75 的是橙色虚线。这些颜色不含当前单元的红。
- 单元队列里，红色实心是当前要核对的单元，灰色细框是其他预标注，不用管，橙色虚线是你的选区。同一页上另外还在复核集里的单元用灰色点线和队列序号，不会画成红色。每次用队列、Enter、`j` 或 `k` 换单元，画面会留出滚动空白，把这个红框滚到视口中间。默认缩放也一样。
- 缺 PDF 时，中间会出现深红色横幅，右栏的选中数和元素列表会清空，不管是打开的第一篇，还是后来用 `j`、`k` 或队列点进去的。横幅会写出缺少的 `corpus/pdfs/<id>.pdf`，以及要手动下载或用 `--import`。这时确认和改标签不起作用，不会把没看见的单元记成已复核。`j` 和 `k` 仍可离开这一篇。这一次会话里已经打开过的论文，如果之后 PDF 被删掉，下次再打开会丢掉这份缓存并重新出现横幅。快速连按 `j` 时，pdf.js 取消上一帧绘制是预期情况，不会当成错误。
- 点击只选中一个字形。右栏会写「选中 N 个」，并按单元列出全部选中元素。选区里如果混进了不属于当前红色单元的元素，会单独列在「选区里还有这些（不属于当前单元）」下面。右栏可以滚动。
- `1` 公式，`2` 正文，`3` 代码，`4` 其他。
- `d` 行间，`i` 行内。`e` 标公式编号：只选中 `(1)` 再按 `e`，它会并进同一行旁边的公式单元，并且只有这几个字形标成编号。它已经在那个单元里时，再按 `e` 只切换这几个字形的编号。选中整式再按 `e` 会把整式都标成编号。
- `m` 把当前框选的元素收成一个单元。短符号和路径会改成公式（人工，置信度 1）。带普通单词的宽正文不会改成公式。右栏会列出这段文字。请用 Ctrl 或 Cmd 点击，或按住 Alt 拖动，把它从选区去掉。没框到的成员留在原单元里，这不是错误。只点中一个字形时 `m` 会停住，红字留在右栏，这时按 Enter 不会把这一选区记成已复核。选区变了之后才能确认。
- 选中一个单元里的一部分再按 `s`，这一部分成为新的行内单元，没选中的成员留在原单元。把一个单元全部选中再按 `s`，每个字形各自成一个单元。
- 拖选时，元素的中心要落在方框里，并且大约 60% 的面积也在方框里，才会被选中。整个落在方框里的小下标也会被选中。只擦到边的宽正文不会被选中。按住 Alt 再拖，是从选区里减去。Ctrl 或 Cmd 点一下，可以单独选中或取消一个元素。Shift 仍然往选区里追加。按 `z` 会把当前红色单元放大到大约占画面宽度的一半，最大 400%，再按一次回到刚才的缩放。加号和减号也可以调节缩放。
- 单元队列里，`j` / `k` 是下一个或上一个单元。整页队列里，`j` / `k` 改为在低置信度元素之间跳。`n` / `p` 翻页。
- 默认队列是 `labels/review-set.json` 里的 1000 个单元，种子 `20260925`。六个领域尽量均分，每个领域里再按来源均分，抽样偏向低置信度，同时照顾行间、行内和公式编号。队列顺序按领域轮转，每个领域里再按论文编号轮转，所以前面的条目会换论文。名单和种子不变，只改了顺序。生成命令是 `node scripts/review-set.mjs`。复核前不要重新生成。
- 点队列里的一条会打开那一页，并把该单元滚到视口中间。Enter 或「看过，下一个」把这个单元 id 写入该页的 `reviewedUnitIds`，顶栏变成「已复核 37/1000 个单元」，然后跳到下一个还没看的单元。若那一页的 PDF 不在，横幅会再出现。
- 「整页队列」仍按低置信度元素多少列出页面。
- 改动大约 0.4 秒后写入 `labels/reviewed/<论文>/page-NNN.json`。这个目录可以提交。接触图和检查缓存不提交。

导出和导入：

- 「导出」把当前页 JSON 下载到 Chrome 的下载目录，当作备份。要提交的是服务已经写好的 `labels/reviewed/<论文>/page-NNN.json`，不是下载目录里的那份。
- 「导入」读一份 JSON，先做编号校验，通过才写入 `labels/reviewed/`。被拒绝时提示是中文，并说明要用本页导出的文件，不要手改元素编号、字符或框。
- 做完一批后：`git add labels/reviewed`，再提交。不要提交 `corpus/pdfs/`。`git status` 里不应出现基线文档的改动。

接触图（左：页面轮廓，中：基线 SVG，右：差异。红色是页面有而 SVG 没有）：

```
node scripts/contact-sheet.mjs --paper 1706.03762 --page 4
```

复核页里的「接触图」链接会生成同一页。图片在 `labels/sheets/`，不提交。

## 自动检查

```
node scripts/baseline-checks.mjs
```

这个命令不下载。磁盘上有哪些 PDF 就检查哪些，缺少的会列出来并跳过，结尾的汇总里会再列一次。进度会打印到终端。默认结果写到 `labels/checks/baseline-report.md` 和 `labels/checks/baseline-summary.json`，这两个路径被 git 忽略。耗时只打印在终端，不写进文件。缓存按论文 id、内容指纹和预标注版本一起核对，指纹或规则变了会重算。跑完以后 `git status` 应当仍是空的（除了你正在写的 `labels/reviewed/`）。

仓库里的 `docs/v1-m1-baseline.md` 和 `labels/baseline-summary.json` 只有加上 `--write-docs` 才会更新，而且这两份里没有耗时列。复核时不需要跑 `--write-docs`，也不必提交它造成的差异。

表里的数字对着未复核的预标注，不会改用 `labels/reviewed/`。基线选择器是 M0 的 `lib/formula-svg.js`，这里没有改它。

- A1：单元裁切矩形里的每一个像素。左边是 pdf.js 关闭字体、画出的轮廓（和录制看到的是同一层墨），右边是基线 SVG。左边有墨、r = 1 内 SVG 没有墨，就计缺笔。
- A2：进了公式 SVG、但标注不是公式的元素。看的是标注，不是选择器自己的字体判断。
- A3：和预标注单元的元素集合是否完全一致，另外给平均 Jaccard。
- 空 SVG：文本层公式块里，SVG 为空的比例。这不是 A4。
- A4：预标注公式单元里，自报置信度低于 0.65 的比例。这不是准确率。上下标接合（0.55）和粘合段（0.50）是常数，没有独立正确率，所以落在这条线下面。
