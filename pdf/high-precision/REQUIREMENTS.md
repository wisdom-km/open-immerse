## 1. 一句话目标

只忠于用户打开的那份 PDF。第一优先级是内容精准：译文跟抽出的原文一致；公式、图、表跟原文是同一套内容。手段可以用裁图，也可以用别的，只要精准仍在。排版优先级低于精准，同时尽量做到最高。本地 GLM-OCR 只做测试；上线走 OCR API 与大模型 API。

### 1.1 优先级（2026-09-22 确认）

| 序 | 目标 | 做到什么程度 |
| --- | --- | --- |
| 1 | 内容精准 | 硬目标。译文不增、不漏、不改原文的主张。公式、图、架构图、曲线、表的内容与打开的 PDF 一致。`i` 被认成 `n`，或 `n` 被认成 `i`，都算失败 |
| 2 | 排版 | 低于内容。阅读顺序、左右对照、点击对齐、不叠字、字号可读，这些尽量做到最高。任何排版都不得改写上一条 |

公式和图的做法不锁死成唯一技术。当前已上线的是原页高清重渲染（`pdf/viewer.js` 的 `renderSharpVisualCrop`）或 pageRaster 的 png 裁图，因为这条已经能保住笔画。内嵌图原样取出、原页矢量原样搬过来，也可以，只要右栏结果仍与打开的 PDF 同一套内容。图内英文重画达不到精准，仍不采用。把公式认成 LaTeX 再渲染，只允许作为 §2.6 的第二层（作者源码的第零层见 §2.7），前提是 Aa 面板里的「用看图模型补全公式」开着并且通过字符核对。运行时第二层排在第一层之前，见 §2.6「运行时顺序」。这个开关待实现：用户接上多模态 API 后显示，默认关闭，开关旁注明费用和隐私（2026-10-05 00:33 Wisdom 定）。DPO 论文（arXiv 2305.18290v3）第 3–5 页 79 个公式是多模态准确率的参考测试：不是合入或上线的门槛（2026-10-05 00:48 Wisdom 定，取代 2026-10-02「第二层在 DPO 测试前保持关闭」）；接上 API 后先跑一次，结果给 Wisdom 看（据 00:48 决定整理）。第三层占位是另一个开关（也待实现，代码里现在没有），默认关闭，独立公式和行内公式共用这一个，见 §2.6。已上线的高清重渲染和 png 裁图都按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层按 §2.6「运行时顺序」的自动判据。

PDF 带 arXiv 编号、用户点了「用 arXiv 源码校准公式」时，公式可以改用作者的 LaTeX 源码，叫第零层，见 §2.7。源码只是帮我们更准地还原这份 PDF：每个公式都要先和这份 PDF 核对通过才上屏，没过就按 §2.6 走。「只忠于用户打开的那份 PDF」不变。

### 2.4 准确度目标（能做多高做多高）

没有开源方案能对「任意 PDF + 任意句译文」签 99% 的法律保证。本项目用技术选型把 **可保证的部分推到接近 99%**，把不可保证的部分隔离并写明。

| 项 | 数字发表 PDF（主场景） | 扫描件（保留能力） |
| --- | --- | --- |
| 公式视觉 | 目标 **≥ 99%**，适用于任何一层上屏的结果 | 与该页扫描件一致（糊/歪属原件） |
| 图 / 架构图 | 目标 **≥ 99%**，适用于任何一层上屏的结果 | 同上 |
| 表（当图） | 目标 **≥ 99%** | 同上 |
| 正文是否抽全、抽对 | 文字层路径目标 **尽量 99%**；框划错会掉点 | OCR 上限，允许低于数字 PDF，界面提示 |
| 译文相对「抽出的原文」 | 尽量高（强模型 + 术语表 + 只译人话）；**不是公式那种像素级 99%** | 错字会传递到译文 |

内容精准是硬目标，排版是第二目标。公式、图、表用「与打开的 PDF 同一套内容」来验收，不把某一种裁图函数写成唯一合法手段。译文用强 LLM API、术语约束、数字和变量名原样保留来逼近；不在第一版用自动 BLEU 当门槛，也不为了更好看的段落去改主张。排版在不伤害内容的前提下尽量做好：阅读序、分栏不串、点击能对回原文栏、右栏不叠字。

### 2.5 部署与 API（必须预留）

| 阶段 | OCR 划区 | 翻译 |
| --- | --- | --- |
| 本地测试 | 本机 GLM-OCR | 插件已配置的大模型 API，或小规模购买 API |
| 小规模试 API | 智谱 GLM-OCR 等云 API（同一 JSON） | 同上（Ark / DeepSeek / OpenAI 兼容） |
| 上线 | **只走 OCR API + LLM API** | 密钥仍在用户/产品配置的 `chrome.storage` |

架构上 **本地引擎与云 API 必须同一套块协议**。换后端只换 adapter，不改右栏渲染和裁图逻辑。  
**公式、图、表的内容永远来自用户打开的 PDF，不来自 OCR API 返回的字母。** 第零层例外：公式可以取自作者的 arXiv 源码，但必须逐条通过和这份 PDF 字符的核对，见 §2.7。现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。高清重渲染失败时静默退成 png。目标是按原字体、原位置重绘字符。换层按 §2.6「运行时顺序」的自动判据。换一种展示手段时，验收仍是同一套内容。这样上线接 API 也不会再出现 i/n 互认。

**第二层核对。** 核对依据仍是 PDF 里的原字符，但不能直接用第一层那个框里的字符。到第二层的公式里有不少框不准：框吞进了下一行正文，或长公式被切成几块。拿这个框里的字符去比，会和第一层的框错误循环依赖。

第二层自己取字符。同一个独立公式被切成几块时，先把同一公式区域里相邻、中间没有正文行的第一层框合并，再扩大。「相邻」的距离待实验定。然后在扩大后的区域里重新圈取 PDF 字符，再去掉明显的正文行和公式编号。不使用第一层框内原有的那份字符清单。已知局限：取字先按第一层的框外扩，框本身不准会影响核对。下面的数字都是初始值，由 DPO 离线实验校准。

- 正文行高：本页文字层里，非数学字体字形高度的中位数。取不到时，用本页全部文字项高度的中位数。
- 初始扩大：从合并后的框的四边向外，上、下各扩 1 个正文行高，左、右各扩 2 个正文行高。只收集中心点落在扩大后区域内的 PDF 字符。
- 正文行：同一基线上的字形里，数学字体占比不到一半，并且含有一个 4 个及以上英文字母的词，或连续 2 个及以上汉字。函数名 softmax、LayerNorm、Attention、MultiHead、Concat、sqrt、exp、log、sin、cos、tan、max、min 不算这种词。正文行从核对用的字符里去掉。
- 公式编号：只去掉最右侧、和公式主体分开的编号括号。括号里是数字、点、字母加数字的组合，例如 (2)、(2.3)、(A1)、(3a)。公式主体内部的括号不去掉。左右扩大时收到的这种编号不进比较集合。

比较的是字符集合：LaTeX 里出现过的字母、数字、符号，和 PDF 里出现过的是否一致。不比排版顺序，也不比同一个字符出现的次数。两边的字符先做 NFKC 归一再比。这样字母类符号区的 ℝ（U+211D）和数学字母数字区的字母都会归到 ASCII 字母。ℝ 在字母类符号区，不在数学字母数字区。U+1D538 起的双线体里 C、H、N、P、Q、R、Z 的位置是空的，实际用的是字母类符号区的码点。已知局限：NFKC 会把 ℓ（`\ell`，U+2113）收成字母 l，和普通字母 l 混淆，可能误放。省略号 … 和 `\ldots` 两边都会变成三个点，结果一致。实验里要统计这类情况。源码里的减号 `-` 和 PDF 里的 U+2212（−）视为同一个字符。希腊字母的变体互相接受：ϵ（U+03F5）和 ε（U+03B5），ϕ（U+03D5）和 φ（U+03C6），ϑ（U+03D1）和 θ（U+03B8）。不同字体对变体的字形和码点并不一致。`\cdot` 同时接受 U+00B7 和 U+22C5。初始通过阈值是两边集合的 Jaccard 相似度 ≥ 0.9（交集大小除以并集大小）。这也是初始值，由 DPO 离线实验校准。

**网络和隐私。** 第零层给扩展加了一条新的网络请求：从 `background/` 直接连 arxiv.org 下载源码包。下载会让 arXiv 知道用户在读哪篇论文（以及用户的 IP）。所以默认关闭，点了才下。源码只在本机解析和缓存，不上传，不经本地库服务转发，不进仓库。arXiv 条款允许为个人使用或研究取用、保存 e-print，不允许在自己的服务器上存储或提供。

**和别的条款的关系。** §1「只忠于用户打开的那份 PDF」不变。§2.5「公式、图、表的内容永远来自用户打开的 PDF」：第零层例外，前提是逐条核对通过。§2.3「未经核对就把公式认成 TeX 再渲染」：第零层核对过，不冲突。第零层和第二层共用核对映射表，区别是第二层的 LaTeX 是模型猜的，第零层的 LaTeX 是作者写的。图仍是 PDF 裁图，表仍整表当图。引用编号、交叉引用编号、页码这些 TeX 编译时才生成的数字，源码里没有，仍取自 PDF。

## 6. 块协议（本地与 API 必须一致）

```json
{
  "page": 3,
  "width": 612,
  "height": 792,
  "blocks": [
    {
      "id": "p3-b12",
      "label": "text",
      "bbox": [0.12, 0.40, 0.48, 0.55],
      "text": "We propose the Transformer..."
    },
    {
      "id": "p3-b13",
      "label": "formula",
      "bbox": [0.15, 0.56, 0.85, 0.62]
    },
    {
      "id": "p3-b14",
      "label": "figure",
      "bbox": [0.10, 0.10, 0.90, 0.38],
      "caption": "Figure 1: The Transformer architecture."
    },
    {
      "id": "p3-b15",
      "label": "table",
      "bbox": [0.12, 0.70, 0.88, 0.92]
    }
  ]
}
```

约定：

- `bbox`：归一化 `[x0,y0,x1,y1]`，与 pdf.js viewport 相乘即可裁图和高亮。
- `label`：`title` | `text` | `caption` | `formula` | `figure` | `table` | `header` | `footer`。
- **仅** `title` / `text` / `caption` 带 `text`，且数字 PDF 的 `text` **优先来自文字层与框的对齐**，不是 OCR 猜的公式字母。
- `formula` / `figure` / `table` 不带 OCR 或划区 API 返回的 `latex`。这类 API 若返回 LaTeX，适配器丢弃，不得进入右栏。只有 §2.6 第二层和 §2.7 第零层的适配器在核对通过后，可以给该 `formula` 同时带上三个字段，缺一则整组丢弃、不得上屏：`latex`（核对通过的 LaTeX 字符串）、`latexSource`（来源：第二层取 `"vlm"`，§2.7 第零层取 `"arxiv-src"`）、`verified`（必须为 `true`）。`figure` 和 `table` 仍然不得带这三个字段。
- `caption` 可译；图本身只裁图。

## 7. 核心流程

```
1. 用户打开 PDF
2. 原文栏立刻用 pdf.js 渲染原文（不等划区）
   （第零层，§2.7）PDF 带 arXiv 编号时，状态栏给「用 arXiv 源码校准公式」。用户点了（或勾过「以后自动」），background/ 下载这一版源码、解包、存本机；对齐后逐个公式核对。下载放后台，不挡原页
3. 插件把 PDF（或逐页渲染图 + 文字层）交给划区后端
     测试 → 本机 GLM-OCR
     试跑/上线 → OCR API
4. 后端只返回 blocks[]（框 + 正文原文）
5. 插件按 bbox 保住公式/图/表：现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。高清重渲染失败时静默退成 png。目标是按原字体、原位置重绘字符。换层按 §2.6「运行时顺序」的自动判据。其他手段须与原页同一套内容
6. 可译块（title/text/caption）→ OI_TRANSLATE_BATCH
     术语表 + 不译数字/占位符
7. 右栏按阅读序：
     译文段落
     公式 = 按 §2.6「运行时顺序」，每一步没过自动判据就交给下一步：
            第零层（§2.7，开着且这个公式核对通过，用作者源码的 KaTeX）
          → 多模态（第二层：接上 API、开关开着、核对通过，用 KaTeX）
          → 矢量重绘（第一层：把握分数过阈值；待实现）
          → 原页裁图（第一层：清楚、没切到邻行）
          → 占位（第三层：开关开着才用，否则显示现状）
            没接多模态 API 时从矢量重绘开始
     图 = 按 §2.6：裁得准就放进译文并配译后题注，裁不准走占位
     表 = 原页裁图
8. 点击右栏块 → 原文栏 scrollIntoView + 高亮同一 bbox。公式三层共用的点击跳转见 §2.6
9. 无文字层：正文改走 OCR 字，界面提示「本页可能为扫描件，正文或有识别误差」
```

数字论文主路径：**正文 = 文字层 ∩ 正文框**；**表 = 原页图**；公式和图按 §2.6。扫描件只替换「正文从哪来」，裁图逻辑不变。

## 8. 准确度如何靠技术栈撑起来

| 风险 | 对策 |
| --- | --- |
| 公式 OCR 把 n 认成 i | 公式不上 OCR 字母。当前已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。高清重渲染失败时静默退成 png。第二层输出必须过 §2.6「第二层核对」 |
| 行内公式被当正文送去翻译 | 行内也标 `formula`。路径见 §2.6「行内公式」 |
| 图被重绘译坏 | 图内不译 |
| 表结构译乱 | 整表当图 |
| 正文抽错、抽漏 | 数字 PDF 用文字层；划区框与文字层求交；页眉页脚丢掉 |
| 译文不忠于原文 | 强 LLM API；按段；术语表；只译人话 |
| 上线 API 变差 | 裁图仍在浏览器；API 只划区 |

验收（建议用 Attention is All You Need 及另一份非 arXiv 的出版社 PDF）：

- 右栏公式与原文栏同一位置肉眼一致，抽查无 n/i 类改字
- 架构图与原文一致，图内英文未被改
- 表为原图表，未拆格
- 右栏段落能点回原文栏对应句
- 关闭本地引擎、改 OCR API 后，当前已发布的仍是区域渲染，按 §2.6 算第一层。不回归未经核对的「认 LaTeX」；核对通过的第二层见 §2.6
