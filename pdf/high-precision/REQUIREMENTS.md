## 1. 一句话目标

只忠于用户打开的那份 PDF。第一优先级是内容精准：译文跟抽出的原文一致；公式、图、表跟原文是同一套内容。手段可以用裁图，也可以用别的，只要精准仍在。排版优先级低于精准，同时尽量做到最高。本地 GLM-OCR 只做测试；上线走 OCR API 与大模型 API。

### 1.1 优先级（2026-09-22 确认）

| 序 | 目标 | 做到什么程度 |
| --- | --- | --- |
| 1 | 内容精准 | 硬目标。译文不增、不漏、不改原文的主张。公式、图、架构图、曲线、表的内容与打开的 PDF 一致。`i` 被认成 `n`，或 `n` 被认成 `i`，都算失败 |
| 2 | 排版 | 低于内容。阅读顺序、左右对照、点击对齐、不叠字、字号可读，这些尽量做到最高。任何排版都不得改写上一条 |

公式和图的做法不锁死成唯一技术。默认是从原页裁图，因为这条已经能保住笔画。内嵌图原样取出、原页矢量原样搬过来，也可以，只要右栏结果仍与打开的 PDF 同一套内容。图内英文重画达不到精准，仍不采用。把公式认成 LaTeX 再渲染，只允许作为 §2.6 的第二层，前提是用户开启并且通过字符核对。拿不准时走 §2.6 第三层（点击看原文）。现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层只看框的把握。

### 2.2 必须极准

| 对象 | 标准 | 做法 |
| --- | --- | --- |
| 公式（含行内） | 与原文同一套内容；禁止 i/n 互认 | 现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层只看框的把握。其他手段可以，验收标准相同。不展示未经核对的 LaTeX（见 §2.6） |
| 图、架构图、曲线图 | 与原文同一张图 | 裁得准就放进译文，配上译后题注；裁不准走 §2.6 的占位。图内英文不重绘、不翻译 |
| 表 | 第一版视觉与原文一致 | 默认整表当图，不译格子。其他手段也要整表内容不变 |
| 正文原文 | 数字 PDF 用文件里的字，不是猜的 | **优先 PDF 文字层原句** |
| 译文 | 跟抽出的原文内容精准 | 只译标题、段落、题注；公式/图/表不进模型。措辞顺滑让路给忠实 |
| 对应关系 | 读者能对上「这段译文 ↔ 原文哪一块」 | 每块 `page + bbox` |

行内公式：夹在句子里的符号也拆出去单独保住。路径见 §2.6「行内公式」。字母不送给 OCR，也不送给翻译。

公式在右栏展示原文内容。不做可复制 LaTeX。层与层之间只看框的把握。框的把握分数过阈值，就用第一层；没过阈值时，如果第二层开着并且核对通过，就用 KaTeX；否则用第三层的占位。第一层的目标是按原字体、原位置重绘字符。做出来之前，现有的 `surface="redraw"` 也算第一层，本质上是原页区域的高清重渲染。矢量画不出来退成 png，静默、不加徽章（V1-B1），不算换层。

### 2.3 明确不做（第一版）

- 可复制 LaTeX（仍然不做）
- 未经核对就把公式认成 TeX 再渲染（核对通过的第二层见 §2.6）
- 图内文字译成中文并重画
- 翻译表格单元格
- 生成「长得像原论文」的中文 PDF（BabelDOC 整页回写）
- 多模态「看一整页直接出中文」
- 把译文糊进原 PDF 文字框（bbox 镜像；仓库内 #40 已否决）

### 2.4 准确度目标（能做多高做多高）

没有开源方案能对「任意 PDF + 任意句译文」签 99% 的法律保证。本项目用技术选型把 **可保证的部分推到接近 99%**，把不可保证的部分隔离并写明。

| 项 | 数字发表 PDF（主场景） | 扫描件（保留能力） |
| --- | --- | --- |
| 公式视觉 | 目标 **≥ 99%**，适用于任何一层上屏的结果 | 与该页扫描件一致（糊/歪属原件） |
| 图 / 架构图 | 目标 **≥ 99%**，适用于任何一层上屏的结果 | 同上 |
| 表（当图） | 目标 **≥ 99%** | 同上 |
| 正文是否抽全、抽对 | 文字层路径目标 **尽量 99%**；框划错会掉点 | OCR 上限，允许低于数字 PDF，界面提示 |
| 译文相对「抽出的原文」 | 尽量高（强模型 + 术语表 + 只译人话）；**不是公式那种像素级 99%** | 错字会传递到译文 |

内容精准是硬目标，排版是第二目标。公式、图、表用「与打开的 PDF 同一套内容」来验收，不把某一种裁图函数写成唯一合法手段。译文用强 LLM API、术语约束、数字和变量名原样保留来逼近；不在第一版用自动 BLEU 当门槛，也不为了更好看的段落去改主张。排版在不伤害内容的前提下尽量做好：阅读序、分栏不串、点击能对回原文栏、右栏不叠字。

### 2.5 部署与 API（必须预留）

| 阶段 | OCR 划区 | 翻译 |
| --- | --- | --- |
| 本地测试 | 本机 GLM-OCR | 插件已配置的大模型 API，或小规模购买 API |
| 小规模试 API | 智谱 GLM-OCR 等云 API（同一 JSON） | 同上（Ark / DeepSeek / OpenAI 兼容） |

架构上 **本地引擎与云 API 必须同一套块协议**。换后端只换 adapter，不改右栏渲染和裁图逻辑。  
**公式、图、表的内容永远来自用户打开的 PDF，不来自 OCR API 返回的字母。** 现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层只看框的把握。换一种展示手段时，验收仍是同一套内容。这样上线接 API 也不会再出现 i/n 互认。

### 2.6 公式三层方案（2026-10-02 确认）

每个公式按三层依次尝试。上一层没把握，就交给下一层。运行时顺序是 1 → 2 → 3。开发按优先级：第一层和第三层先做（P1），第二层后做（P2）。

| 层 | 做法 | 优先级 | 可行性 | 何时采用 |
| --- | --- | --- | --- | --- |
| 第一层 | 目标是按原字体、原位置重绘字符。做出来之前，`surface="redraw"` 的原页区域高清重渲染也算第一层，本质上是区域渲染。矢量画不出来退成 png，静默、不加徽章（V1-B1），不算换层 | P1，先做 | 中 | 框的把握分数过阈值 |
| 第二层 | 看图大模型转成 LaTeX，再用 KaTeX 渲染 | P2，后做 | 中 | 框的把握没过阈值，且用户开启，且字符核对通过 |
| 第三层 | 点击看原文：独立公式用写明位置的占位加小缩略图。文案是目标状态，待实现：有编号「公式 (n) · 原文第 N 页」，没有编号「公式 · 原文第 N 页」，跨页「第 4–5 页」。点击后原文栏跳到原位并画框；没有框时只跳到页顶。原页裁图在原文栏里看；原文区隐藏时临时弹出原文。只有这种占位不把原页裁图嵌在译文里 | P1，先做 | 高 | 框的把握没过阈值，且第二层没采用 |

**第一层：按原字体、原位置重绘字符（P1，可行性中）。** 目标是把公式字符按原字体、原位置画到右栏。在这做出来之前，现有的 `surface="redraw"` 也算第一层。它在 `pdf/viewer.js` 的 `renderSharpVisualCrop`（约第 978 行）和 `withRasterCrop`（约第 1067–1081 行）里，把原页这块区域高清重新渲染；`lib/pdf-formula-redraw.js` 的 `redrawFormulaGlyphs` 是从原页光栅上按字形位置贴像素。这本质上是区域渲染，还不是按原字体逐字矢量重绘。第一层内部，矢量画不出来时退成 png（`surface="png"`）。这是同一块内容换一种渲染方式，静默回退，不加徽章（V1-B1），不算换层。层与层之间只看框的把握：框的把握分数过阈值，就用第一层；没过阈值时，如果第二层开着并且核对通过，就用 KaTeX；否则用第三层的占位。画面来自打开的 PDF，所以符合 §1 的「同一套内容」。但前提是框要准，而现在的框准率很低：要认出出版社的数学字体，并修掉两类错误——公式框吞进下一行正文，以及长公式被切成好几块。每个公式还要输出一个把握分数。这个分数用练习集校准：分数说有把握时，结果要真的对。

**当前基线（2026-10-02）。** A3 是和预标注单元的元素集合完全一致（精确命中），另外还有平均 Jaccard；定义见 `docs/v1-m1-baseline.md`。下面这组计数不在该文件里。来源：2026-10-02 Anvil 验证报告。练习集 #1–#277 上 main 的 A3 精确命中是 36/258。引用上标过滤（R1）收益为 0。数学字体名单（R2）只加字体名修好 0 条，放宽到全部 Adv* 字体的理论上限是 25/258。DPO 论文第 3–5 页上 main 对 32/79。第一层要靠第一步的识别改进把框准率提上去，在此之前大部分公式会落到第二层或第三层。

**第二层：看图大模型（P2，可行性中）。** 框的把握没过阈值时，把这个公式的原页区域交给多模态模型，转成 LaTeX，再用 KaTeX 渲染。代价是要付费、必须联网、用户要自己配 key，公式图会发给第三方。模型也可能写错，看起来却像是对的。硬约束有三条：

1. 模型输出必须按下面的「第二层核对」和 PDF 里的原字符比对。对不上，或 PDF 字符无法可靠映射，就丢弃，降到第三层。
2. 继续默认关闭。等 DPO 论文（arXiv 2305.18290v3）第 3–5 页 79 个公式的离线实验出了准确率，再决定上不上线。
3. 这套核对规则放进上述离线实验里评估。实验仍要报告能补回多少个第一层没把握的公式。核对本身分别统计「转对却被判错」和「转错却被放行」的数量。本文不写这些数量。结果交产品方，由产品方决定是否上线。

**第二层核对。** 核对依据仍是 PDF 里的原字符，但不能直接用第一层那个框里的字符。掉到第二层的往往正是框不准的公式：框吞进了下一行正文，或长公式被切成几块。拿这个框里的字符去比，会和第一层的框错误循环依赖。

第二层自己取字符。同一个独立公式被切成几块时，先把同一公式区域里相邻、中间没有正文行的第一层框合并，再扩大。然后在扩大后的区域里重新圈取 PDF 字符，再去掉明显的正文行和公式编号。不使用第一层框内原有的那份字符清单。下面的数字都是初始值，由 DPO 离线实验校准。

- 正文行高：本页文字层里，非数学字体字形高度的中位数。取不到时，用本页全部文字项高度的中位数。
- 初始扩大：从合并后的框的四边向外，上、下各扩 1 个正文行高，左、右各扩 2 个正文行高。只收集中心点落在扩大后区域内的 PDF 字符。
- 正文行：同一基线上的字形里，数学字体占比不到一半，并且含有一个 4 个及以上英文字母的词，或连续 2 个及以上汉字。函数名 softmax、LayerNorm、Attention、MultiHead、Concat、sqrt、exp、log、sin、cos、tan、max、min 不算这种词。正文行从核对用的字符里去掉。
- 公式编号：行末的「(n)」从比较集合中去掉，避免左右扩大时把编号收进来。

比较的是字符集合：LaTeX 里出现过的字母、数字、符号，和 PDF 里出现过的是否一致。不比排版顺序，也不比同一个字符出现的次数。源码里的减号 `-` 和 PDF 里的 U+2212（−）视为同一个字符。初始通过阈值是两边集合的 Jaccard 相似度 ≥ 0.9（交集大小除以并集大小）。这也是初始值，由 DPO 离线实验校准。

LaTeX 命令先映射成字符再进集合。下面是初始映射表。未列出的命令要计数，并写进实验报告。实验下结论前先把这些命令补进表。映射表不全不能成为公式落到第三层的主要原因。

| LaTeX | 计入比较的字符 |
| --- | --- |
| `\alpha` `\beta` `\gamma` `\delta` `\epsilon` | α β γ δ ε |
| `\theta` `\lambda` `\mu` `\pi` `\sigma` `\phi` `\omega` | θ λ μ π σ φ ω |
| `\partial` `\nabla` | ∂ ∇ |
| `\infty` `\sum` `\prod` `\int` | ∞ ∑ ∏ ∫ |
| `\sqrt` | √；根号里的字符另计 |
| `\frac` | 分子和分母里的字符；命令名不计入 |
| `\leq` `\geq` `\neq` `\times` `\cdot` `\pm` | ≤ ≥ ≠ × · ± |
| `\rightarrow` `\leftarrow` `\in` `\subset` | → ← ∈ ⊂ |
| `\{` `\}` | { } |
| `\cdots` `\ldots` `\dots` | `\cdots` → ⋯；`\ldots` 与 `\dots` → … |
| `\hat` `\bar` `\tilde` `\vec` | 只取底字，命令名不计入 |
| `\log` `\exp` `\max` `\min` `\arg` | log、exp、max、min、arg 的字母 |
| `\left` `\right` | 不计入 |
| `\mathrm` `\mathbf` `\mathcal` | 取里面的字母和数字，命令名不计入 |

源码里的英文字母和数字按原样计入。其余纯排版命令不计入比较：`\bigl` `\bigr` 这一组、`\displaystyle` `\textstyle` `\scriptstyle`、`\,` `\;` `\:` `\!` `\quad` `\qquad`、`\hspace` `\vspace`、`\limits` `\nolimits`、`\mathit` `\mathbb` `\operatorname`（命令本身不计入，里面的字母和数字计入）、`\begin` `\end` 和环境名、对齐用的 `&` 和 `\\`、上下标的 `^` `_` 和分组用的花括号。

PDF 字符无法可靠映射时，不做核对，直接走第三层。初始判断：扩大区域内有字形的字体名以 `Adv` 开头，并且该字形没有可用的 Unicode（空、`.notdef`，或落在专用区 U+E000–U+F8FF）。出现任一这样的字形，整式降到第三层。已知限制：Adv 类字形如果带着错误的 Unicode 映射（有码点，但不是公式里的那个字符），核对此可能抓不到。实验要单独统计这类字体上的放行错误（转错却被放行）。

多模态在这一层只接收该公式的原页裁图，只产出待核对的 LaTeX。看一整页直接出中文仍不做，见 §2.3。哪一层出结果，就用哪一层的形式作主展示；这一层出了结果，主展示就是 KaTeX。KaTeX 结果一律带小记号。点小记号是看原图对照。点公式本体也跳转原文，见「点击跳转」。

**第三层：点击看原文（P1，可行性高；2026-10-02 补充）。** 对独立（display）公式，第三层是写明位置的占位，加一张小缩略图。占位文案是目标状态，待实现：有编号写「公式 (n) · 原文第 N 页」，没有编号写「公式 · 原文第 N 页」，跨页写「第 4–5 页」。点击后，原文栏跳到原位并画框；没有框时点击只跳到页顶。原页裁图在原文栏里看；原文区隐藏时临时弹出原文。只有这种占位不把原页裁图嵌在译文里。第一层的区域渲染仍嵌在译文里。屏幕上现在的文字兜底仍是「（公式见左栏）」（`lib/pdf-viewer.js`、`lib/pdf-readout.js`，用在 `pdf/viewer.js`），由 `tests/pdf-viewer.test.mjs` 锁定。这句用在屏幕上，不是导出文案。第三层上线前要在练习集上报告各层占比。占位比例的上线门槛等基线出来后由产品方定。在那之前，不让占位大规模取代现有公式显示。具体 UI 以 Loom 规格为准。

**行内公式。** 行内公式只走第一层，不走第二层的大模型。这里的第一层和独占公式是同一种区域渲染：一小段原页高清重渲染（`surface="redraw"`）。矢量画不出来时静默退成 png，不加徽章（V1-B1），不算换层。这一小段嵌在句中。重点放在这块区域不要伤到阅读。行内公式因为太高而升为独立公式时，仍不走第二层。框的把握过阈值就用第一层；没过就用第三层占位。行内文字兜底是目标状态，待实现：「〔公式 · 原文第 N 页〕」。

**图。** 图也按这一套处理。裁得准，就直接放进译文，配上译后题注。裁不准时用写明位置的占位，例如「图 2 · 原文第 3 页（点击查看）」，加一张小缩略图。点击后，原文栏跳到原位并画框；没有框时点击只跳到页顶。只有这种占位不把原页裁图嵌在译文里：原页裁图在原文栏里看；原文区隐藏时临时弹出原文。裁得准的图仍嵌在译文里。具体 UI 以 Loom 规格为准。

**点击跳转。** 点公式本体也跳转原文，各层都一样：原文栏跳到原位并画框。没有框时点击只跳到页顶。第二层点小记号是看原图对照，不是代替本体跳转。行内公式见「行内公式」。不写「左栏」，写「原文栏」，因为两栏可以互换。具体 UI 以 Loom 规格为准。

**导出。** 下面两句是目标状态，待实现。导出 MD/PDF 时，独立公式写「（公式 (n) 见原文第 N 页）」，图写「（图 n 见原文第 N 页）」。当前导出不走这两句，也不走屏幕上的「（公式见左栏）」。当前导出是 `lib/pdf-blocks.js` 的图片或「见图」。

**分流规则。** 层与层之间只看框的把握。框的把握分数过阈值，就用第一层：目标是按原字体、原位置重绘字符；做出来之前用 `surface="redraw"` 的区域渲染。矢量画不出来退成 png，静默、不加徽章（V1-B1），不算换层。没过阈值时，如果第二层开着并且核对通过，主展示就是 KaTeX，一律带小记号。否则用第三层的占位和小缩略图。只有第三层占位不把原页裁图嵌在译文里。行内公式不进第二层；升成独立公式后也不进第二层。见「行内公式」。

**为什么这么排。** 整套能自动分流，前提是第一层知道自己有没有把握。把握分数不准，再多层也会漏掉错的。

## 3. 从开源抄什么、不抄什么

| 项目 | 借鉴 | 不采用 |
| --- | --- | --- |
| BabelDOC / pdf2zh | 公式和图当原件搬走；只译人话；段级翻译；术语表 | 整段 AGPL 代码；字体正则当唯一公式检测；把译文塞回原框 |
| GLM-OCR / MinerU / PaddleOCR-VL | **只借划区**：label + bbox | **不借公式 LaTeX 上屏**（已实测会把 n 认成 i）。核对通过的第二层见 §2.6，不走这条 OCR LaTeX |
| 沉浸译现有 PDF 轨 | 左 pdf.js、右通读、`OI_TRANSLATE_BATCH`、实验室开关 | 文字层「恢复 LaTeX」作为公式主路径 |

核心原则：**分类用模型，展示用原文，翻译只用自然语言。** 公式第二层见 §2.6。

## 4. 总体架构

Chrome MV3 跑不动 0.9B 视觉模型。拆成三层：

```
┌──────────────────────────────────────────────────────────┐
│  Chrome 扩展（MIT，D:\open-immerse）                       │
│  左：pdf.js 原文                                           │
│  右：已发布区域渲染算第一层；目标按 §2.6                     │
│  翻译：现有 OI_TRANSLATE_BATCH（LLM API）                   │
│  画面：已发布算第一层的区域渲染，见 §2.6                     │
└────────────────────┬─────────────────────────────────────┘
                     │ 同一 JSON：blocks[]
                     │ 本地 HTTP 或 云 HTTPS（预留）
┌────────────────────▼─────────────────────────────────────┐
│  划区后端（可切换 adapter）                                 │
│  测试：本机 GLM-OCR sidecar                                │
│  试 API / 上线：GLM-OCR API（或同协议的其他 OCR API）        │
│  输出：每块 label + bbox +（仅 text/title/caption 的原文）    │
└──────────────────────────────────────────────────────────┘
```

插件 **不包含** PyTorch、vLLM、GLM-OCR 权重、BabelDOC。上图右栏那一行是现在已发布的做法：区域渲染，按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层只看框的把握。

## 6. 块协议（本地与 API 必须一致）

```json
{
  "page": 3,
  "width": 612,
  "height": 792,
  "blocks": [
    {
      "id": "p3-b12",
      "label": "text",
      "bbox": [0.12, 0.40, 0.48, 0.55],
      "text": "We propose the Transformer..."
    },
    {
      "id": "p3-b13",
      "label": "formula",
      "bbox": [0.15, 0.56, 0.85, 0.62]
    },
    {
      "id": "p3-b14",
      "label": "figure",
      "bbox": [0.10, 0.10, 0.90, 0.38],
      "caption": "Figure 1: The Transformer architecture."
    },
    {
      "id": "p3-b15",
      "label": "table",
      "bbox": [0.12, 0.70, 0.88, 0.92]
    }
  ]
}
```

约定：

- `bbox`：归一化 `[x0,y0,x1,y1]`，与 pdf.js viewport 相乘即可裁图和高亮。
- `label`：`title` | `text` | `caption` | `formula` | `figure` | `table` | `header` | `footer`。
- **仅** `title` / `text` / `caption` 带 `text`，且数字 PDF 的 `text` **优先来自文字层与框的对齐**，不是 OCR 猜的公式字母。
- `formula` / `figure` / `table` 不带 OCR 或划区 API 返回的 `latex`。这类 API 若返回 LaTeX，适配器丢弃，不得进入右栏。只有 §2.6 第二层适配器在字符核对通过后，可以给该 `formula` 同时带上三个字段，缺一则整组丢弃、不得上屏：`latex`（核对通过的 LaTeX 字符串）、`latexSource`（来源，本方案只取 `"vlm"`）、`verified`（必须为 `true`）。`figure` 和 `table` 仍然不得带这三个字段。
- `caption` 可译；图本身只裁图。

## 7. 核心流程

```
1. 用户打开 PDF
2. 原文栏立刻用 pdf.js 渲染原文（不等划区）
3. 插件把 PDF（或逐页渲染图 + 文字层）交给划区后端
     测试 → 本机 GLM-OCR
     试跑/上线 → OCR API
4. 后端只返回 blocks[]（框 + 正文原文）
5. 插件按 bbox 保住公式/图/表：现在已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。目标是按原字体、原位置重绘字符。换层只看框的把握。其他手段须与原页同一套内容
6. 可译块（title/text/caption）→ OI_TRANSLATE_BATCH
     术语表 + 不译数字/占位符
7. 右栏按阅读序：
     译文段落
     公式 = 按 §2.6 分流；未命中第一层、也未走通核对通过的第二层时，走第三层点击看原文
     图 = 按 §2.6：裁得准就放进译文并配译后题注，裁不准走占位
     表 = 原页裁图
8. 点击右栏块 → 原文栏 scrollIntoView + 高亮同一 bbox。公式三层共用的点击跳转见 §2.6
9. 无文字层：正文改走 OCR 字，界面提示「本页可能为扫描件，正文或有识别误差」
```

数字论文主路径：**正文 = 文字层 ∩ 正文框**；**表 = 原页图**；公式和图按 §2.6。扫描件只替换「正文从哪来」，裁图逻辑不变。

## 8. 准确度如何靠技术栈撑起来

| 风险 | 对策 |
| --- | --- |
| 公式 OCR 把 n 认成 i | 公式不上 OCR 字母。当前已发布的公式画面是 `surface="redraw"` 的区域渲染，按 §2.6 算第一层。第二层输出必须过 §2.6「第二层核对」 |
| 行内公式被当正文送去翻译 | 行内也标 `formula`。路径见 §2.6「行内公式」 |
| 图被重绘译坏 | 图内不译 |
| 表结构译乱 | 整表当图 |
| 正文抽错、抽漏 | 数字 PDF 用文字层；划区框与文字层求交；页眉页脚丢掉 |
| 译文不忠于原文 | 强 LLM API；按段；术语表；只译人话 |
| 上线 API 变差 | 裁图仍在浏览器；API 只划区 |

验收（建议用 Attention is All You Need 及另一份非 arXiv 的出版社 PDF）：

- 右栏公式与原文栏同一位置肉眼一致，抽查无 n/i 类改字
- 架构图与原文一致，图内英文未被改
- 表为原图表，未拆格
- 右栏段落能点回原文栏对应句
- 关闭本地引擎、改 OCR API 后，当前已发布的仍是区域渲染，按 §2.6 算第一层。不回归未经核对的「认 LaTeX」；核对通过的第二层见 §2.6

## 9. 建议落地顺序

1. 冻结本文协议；插件增加 `cloud-ocr` / `local-ocr` 开关与 `blocks[]` 类型
2. 右栏：`formula`/`figure`/`table` 改为 canvas 裁图（不依赖后端是否本机）。这是现在已发布的做法；目标做法按 §2.6 分流
3. 本机 sidecar：GLM-OCR → `blocks[]`（测试）
4. 文字层与正文框对齐，作为数字 PDF 的 `text`
5. 翻译侧：术语表 + 过滤非 text 块
6. 同一 adapter 接 GLM-OCR API，小规模付费试跑
7. 无文字层时启用 OCR 正文 + 提示文案
8. （以后可选，不在本文第一版）独立工具导出对照 PDF；表内文字翻译
9. 公式三层方案（§2.6）的开发顺序：先做第一层（目标是按原字体、原位置重绘字符；做出来之前把现有区域渲染接上框的把握分数）和第三层点击看原文（写明位置的占位、小缩略图、点一下原文栏跳到原位并画框），最后做第二层离线实验。离线实验结果交产品方，由产品方决定第二层是否上线
